Chapter 1: Introduction to Node.js

Q. What is Node.js?

  • Node.js is not a library, not a framework.
  • It is a runtime environment where we have to run JavaScript outside the browser.
  • Node.js is single-threaded (but instead of that Node.js handles multiple requests).
  • Node.js is non-blocking.
  • Node.js is a runtime environment for JavaScript and built on Chrome's V8 JavaScript engine.
  • (V8 engine is built for Google Chrome ==> it is a Just-In-Time compiler, not an interpreter).
  • V8 engine is used to convert JS code into machine-understandable code.
  • Node.js is open-source (Open-source means its source code is publicly available). i.e., Developers can use it, inspect the source code, modify it, contribute to it.
  • Node.js is cross-platform. Cross-platform means the same Node.js application can run on different operating systems like Windows, macOS, Linux.
  • Normally, JavaScript runs inside a web browser (like console.log('Hello world'): The browser uses a JavaScript engine to execute JavaScript code).
  • Different browsers use different JavaScript engines, such as Chrome -> V8 engine, Firefox -> SpiderMonkey, Safari -> JavaScriptCore.
  • So Node.js allows JS to execute outside the browser, so Node.js uses the V8 JS engine to execute JS.
Definition: Node.js is a cross-platform, open-source JavaScript runtime environment built on Chrome's V8 engine that allows developers to execute JavaScript code outside of a web browser.
मराठी:
  • Node.js ही कोणतीही library किंवा framework नाही, तर ते एक runtime environment आहे जे JavaScript ला browser च्या बाहेर (म्हणजेच server वर) run करण्यास मदत करते.
  • हे Google Chrome च्या V8 engine वर बनलेले आहे.

Q. Why is Node.js special as a Runtime?

  • V8 engine: Node.js uses Google Chrome V8 engine to compile JS into machine code making it lightning-fast.
  • Built-in APIs: Node.js comes with built-in APIs (like fs for file system, or http for servers) so you can build powerful applications without extra libraries.

Q. Why do we need Node.js?

  • Single language for full-stack development (developers can use JS for both frontend and backend, reducing complexity).
  • High performance: Thanks to the V8 engine, Node.js is super fast and can handle thousands of simultaneous connections with ease.
  • Versatile language.
  • Scalable language.
  • Event-driven & non-blocking I/O: Unlike traditional servers that block a thread for each request, Node.js uses an asynchronous model making it highly efficient for handling multiple tasks.
  • Scalable for modern applications: chat applications, streaming applications, or online gaming.
  • Example: Netflix, LinkedIn, PayPal, Uber.

Q. Is it a language or a framework?

  • Not a library, framework, or programming language. Rather, it's a runtime environment that allows developers to run JS outside of a browser.

Q. Is Node.js built on the V8 JS engine?

  • Node.js uses Google's V8 JavaScript engine.
  • V8 is the same JavaScript engine used by Chrome and Chromium-based browsers.
  • V8 is responsible for executing JavaScript.
  • V8 is primarily written in C++.
  • V8 contains the components required to execute and optimize JavaScript efficiently.
  • V8 uses JIT (Just-In-Time) compilation techniques to optimize JavaScript execution.
IMPORTANT:
  • V8 is a JavaScript engine.
  • V8 uses JIT compilation techniques to compile JavaScript into optimized machine code at runtime.
  • V8's main responsibility is JavaScript execution.
  • Node.js embeds V8 and adds additional runtime capabilities around it.

Q. What does Node.js add to the V8 engine?

  • V8 mainly provides JavaScript execution.
  • Node.js adds runtime APIs and supporting components that allow JavaScript to interact with the operating system and network.
  • Node.js provides APIs/features for:
    • File System operations
    • HTTP networking
    • TCP networking
    • UDP networking
    • Streams
    • Timers
    • Process management
    • Environment variables
    • Operating-system interaction
  • Node.js embeds Google's V8 JavaScript engine and provides additional runtime APIs and capabilities that allow JavaScript to interact with the operating system, file system, network, etc.

Q. Node.js JavaScript vs Browser JavaScript

  • JavaScript running inside a normal browser does not have unrestricted access to the user's local file system.
  • This restriction exists because of browser security and sandboxing.
  • For example: A website should NOT be able to freely execute: deleteFile("C:/Users/User/password.txt");
  • If browsers allowed unrestricted file-system access, it would create serious security problems.
  • Node.js is designed as a runtime environment that provides controlled APIs for interacting with the operating system.
  • It is mainly used for building:
    • Server-side applications
    • Backend applications
    • REST APIs
    • Web servers
    • Real-time applications
    • Network applications

Q. Key Features of Node.js

  • JavaScript Runtime Environment => Executes JavaScript outside the browser.
  • Built on V8 => Uses Google's V8 JavaScript engine.
  • Event-driven => Uses an event-driven programming model.
  • Non-blocking I/O => Handles asynchronous I/O efficiently.
  • Single JavaScript Thread => JavaScript execution primarily happens on one main thread.
  • Highly Scalable - Suitable for handling many concurrent I/O operations.
  • Cross-platform - Runs on Windows, macOS, and Linux.
  • Open-source - Source code is publicly available.
  • Large npm Ecosystem - Provides access to a huge collection of packages.
  • Versatile : Useful for APIs, web servers, real-time applications, microservices, streaming, and network applications.

Q. What is Node.js Architecture?

  • Node.js uses an event-driven, non-blocking I/O model.
  • This architecture allows Node.js to handle many concurrent I/O operations efficiently.
  • Node.js does not need to create a separate JS thread for every incoming request; instead, it uses an event-driven architecture where asynchronous operations can be handled without blocking the main JavaScript thread.
  • This makes Node.js particularly suitable for applications that perform a lot of I/O operations (e.g., REST API, real-time app, chat, streaming, web servers, network apps).

Q. What is meant by Event-driven architecture?

Definition: Event-driven architecture is a programming model where the flow of the application is determined by events. When an event occurs, Node.js executes the corresponding event handler or callback.
  • Event means: simply something that happened (e.g., user click, HTTP request arrive, file reading complete, database query complete, timer finish, socket receive a message).
  • Something Happens => Event occurs => Node.js detects the event => associated handler executes.
  • Node.js provides the EventEmitter from the events module.
  • Note: Node.js follows an event-driven architecture where the application responds to events by executing registered event handlers.

Q. What is non-blocking I/O?

  • I/O means input / output. It refers to operations where your application communicates with something external (e.g., read file, read database, receive network data, receive HTTP request).
  • These operations take time. So what should JavaScript do while waiting? There are 2 approaches:
    • 1. Blocking: It's synchronous (one by one execution). JavaScript waits until the operation completes. JS cannot continue executing the next code until the task is complete.
    • 2. Non-blocking: It's asynchronous. JS does not wait for the file to finish reading. Non-blocking tells us that Node.js doesn't wait for I/O operations. Event-driven tells us how Node.js reacts when those operations are completed.
  • Note: Non-blocking I/O allows Node.js to initiate I/O operations without waiting for them to complete. While the operation is in progress, Node.js can continue executing other tasks.
✔ Non-Blocking = Don't wait while the task is running.
✔ Event-Driven = React when the task is completed.
मराठी:
  • Non-blocking म्हणजे काम चालू असताना JavaScript थांबून राहत नाही, ती पुढचे काम करते.
  • आणि Event-driven म्हणजे काम पूर्ण झाल्यावर callback function द्वारे उत्तर देते.

Q. Scalability

  • Node.js is well suited for building scalable network applications.
  • Its event-driven and non-blocking I/O architecture allows a relatively small number of threads to handle many concurrent I/O operations efficiently.
  • This is especially useful for I/O-intensive applications (REST APIs, chat apps, streaming, web servers).
IMPORTANT:
  • "Single-threaded" does NOT mean Node.js can only do one thing at a time.
  • JavaScript execution primarily happens on a single main thread, but Node.js can use the operating system and its runtime components to handle asynchronous I/O operations (e.g. using a thread pool behind the scenes).

Q. Versatility & NPM Ecosystem

  • Node.js can be used to build many types of applications (REST APIs, Microservices, CLI tools).
  • NPM Ecosystem: npm stands for Node Package Manager. It allows developers to install and use open-source packages and libraries instead of implementing everything from scratch.
  • Example: npm install express
  • npm helps developers reuse packages, speed up development, manage dependencies, and share code.

Q. Streams & Timers

  • Streams: Node.js provides Streams for handling data gradually instead of loading everything into memory at once. Useful for large files, video streaming, network communication.
  • Timers: Node.js provides timer APIs (setTimeout(), setInterval(), setImmediate()) for scheduling operations. Integrated with the event-driven execution model.

Q. Removed features from Node.js (Compared to Browser)

  • window object: The global window object, which is part of web browsers, is absent in Node.js.

  • Web specific APIs: APIs like LocalStorage, SessionStorage, and browser-based fetch (though Node 18+ has a native fetch API, historically it was absent) are not available.

  • Logging & Monitoring: Keeps records of system activity.

Interview Questions (Detailed)

Q1. Is Node.js truly single-threaded?
  • Yes and No.
  • The JavaScript execution itself happens on a single main thread (the Event Loop).
  • However, Node.js uses C++ libraries (libuv) behind the scenes, which maintains a thread pool (default 4 threads).
  • This pool is used to handle heavy I/O operations (like file system, DNS resolution, and crypto operations) asynchronously without blocking the main thread.
Q2. What is the difference between blocking and non-blocking I/O?
  • Blocking I/O forces the application execution to wait until the operation finishes (e.g., fs.readFileSync), preventing any other code from running.
  • Non-blocking I/O (e.g., fs.readFile) initiates the request and immediately moves to the next line of code.
  • It handles the result later via a callback, Promise, or async/await once the operation completes.
Q3. Why does Node.js not have a window object?
  • The window object is part of the Browser Object Model (BOM) used to interact with the browser window, DOM, and frontend-specific APIs (like localStorage).
  • Since Node.js runs on a server and has no graphical browser context or DOM, the window object does not exist.
  • Instead, Node.js has a global object for global scope variables.
Q4. Explain Event-Driven architecture in Node.js.
  • It means the flow of the program is determined by events (e.g., an HTTP request arriving, a file finishing reading).
  • Instead of polling or waiting linearly, Node.js registers event listeners/callbacks.
  • When an event occurs, the system adds it to an event queue.
  • The Event Loop eventually picks it up and executes the associated callback function.
Q5. What are the common types of errors in programming?
  • Syntax Error: When you miss any syntax (e.g., missing a parenthesis or comma).
  • Runtime Error: When the code is syntactically correct but throws an error during execution.
  • Logical Error: When the code doesn't crash but behaves incorrectly or gives wrong output.
मराठी सारांश:
  • Interview मध्ये नेहमी Node.js चे Single-threaded असणे, Blocking vs Non-blocking, आणि Event-driven architecture यावर प्रश्न विचारले जातात.
  • थोडक्यात सांगायचे तर, Node.js मुख्यत्वे एकाच thread वर चालते पण I/O कामांसाठी background मध्ये वेगवेगळ्या threads चा वापर करते.

Chapter 1.5: Project Setup & Package Management

Q. What is a Package in Node.js?

Concept:
  • A Package is a reusable block of code, often containing multiple modules or files, created to solve a specific problem (e.g., creating a server, connecting to a database).
  • It is bundled together with a package.json file that describes its contents and requirements.
  • Packages can be shared globally via the NPM registry, allowing developers to avoid writing repetitive code from scratch.
मराठी सारांश:
  • Package म्हणजे तयार कोडचा एक ब्लॉक, जो एखादे विशिष्ट काम करण्यासाठी बनवलेला असतो (उदा. पासवर्ड encrypt करणे).
  • हा कोड आपण आपल्या प्रोजेक्टमध्ये थेट डाउनलोड करून वापरू शकतो, ज्यामुळे आपल्याला तोच कोड पुन्हा लिहिण्याची गरज पडत नाही.

Q. What are npm and Yarn?

Concept:
  • Both npm and Yarn are JavaScript package managers used to install, update, and manage third-party libraries (dependencies) for your Node.js projects.
  • npm (Node Package Manager) is the default package manager. It is installed automatically when you install Node.js.
  • Yarn is an alternative package manager created by Facebook. It was historically faster than npm, but modern npm versions are equally fast. Yarn needs to be installed separately.
Code Example: Basic Installation Commands
// To install a package globally or locally
npm install express      // Installs the express package using npm
yarn add express         // Installs the express package using Yarn
मराठी सारांश:
  • npm आणि Yarn हे दोन्ही Package Managers आहेत.
  • हे आपल्या प्रोजेक्टमध्ये बाहेरचे code/libraries (उदा. express, mongoose) डाउनलोड आणि मॅनेज करण्यासाठी वापरले जातात.

Q. How to Setup a New Node.js Project (Step-by-Step)?

  • Step 1: Create a Folder — Create an empty folder and open it in VS Code.
  • Step 2: Initialize Project — Generate a package.json file. 
    npm init
    • If you use npm init, it will ask you questions interactively (name, version, description).
    • If you use npm init -y or npm init --yes, it will skip all questions and create the file instantly.
  • Step 3: Install Packages — Install your required dependencies. 
    npm install express
    This automatically creates the node_modules folder and package-lock.json file.
  • Step 4: Create Entry File — Create your main file (e.g., app.js or index.js) and start writing your Node.js code.

Q. How to Setup Node.js with TypeScript (Step-by-Step)?

Concept:
  • Dynamically Typed: JavaScript only catches errors at runtime (e.g., when the server crashes).
  • Statically Typed: TypeScript (TS) adds strict static typing to JavaScript.
  • Compile-Time Safety: It catches errors during development, way before running the code.
  • Developer Experience: It provides excellent autocomplete and IntelliSense directly in VS Code.
  • Step 1: Initialize Project — Create the package.json file. 
    npm init -y
  • Step 2: Install TypeScript & Node Types — Install required TS packages. 
    npm install -D typescript tsx @types/node
    • -D (or --save-dev): Installs these packages as development dependencies (they won't be included in the final production build).
    • typescript: The official compiler that converts (compiles) your TypeScript code into standard JavaScript.
    • tsx: A modern and fast execution engine (built on esbuild) that allows you to run TypeScript files directly during development. It completely replaces the older ts-node which often faces issues with ES Modules (like ERR_MODULE_NOT_FOUND).
    • @types/node: Provides type definitions for core Node.js modules (like fs, path), giving you excellent autocomplete and error-checking in VS Code.
  • Step 3: Generate TS Config File — Define compiler rules. 
    npx tsc --init
    • npx: Node Package Execute. It runs the package directly from the npm registry without needing to install it globally on your computer.
    • tsc: Stands for TypeScript Compiler. It is the tool that actually converts your TypeScript code into JavaScript.
    • --init: A flag that tells the compiler to generate a default tsconfig.json setup file in your project.
    • tsconfig.json: The configuration file where you define compiler rules (e.g., "outDir": "./dist" to save compiled files, and "rootDir": "./src" for source files).
  • Step 4: Create Source Folder — Create a src folder and add an app.ts file inside it.
  • Step 5: Add Scripts — Open package.json and add scripts to run and build your code.
Code: package.json (TS Scripts Setup)
"scripts": {
  "dev": "npx tsx src/app.ts",      // Runs TypeScript directly and perfectly handles ES modules
  "build": "tsc",                   // Compiles TypeScript into standard JavaScript
  "prod": "node dist/app.js"        // Runs the compiled JavaScript in production
}
मराठी सारांश (TS Setup):
  • Node.js मध्ये TypeScript वापरण्यासाठी आपल्याला npm init -y नंतर typescript आणि @types/node इन्स्टॉल करावे लागतात.
  • npx tsc --init मुळे TS config फाईल बनते.
  • आपण डेव्हलपमेंटसाठी tsx वापरतो जे थेट .ts फाईल चालवते आणि जुन्या ts-node पेक्षा अधिक जलद आणि error-free आहे.

Q. Difference between `tsx` and `ts-node` (Why we use `tsx` now?)

Concept:
  • Both tsx and ts-node are engines used to run TypeScript files directly during development without needing a separate compile step.
  • ts-node (The Old Way): It is the traditional engine but it struggles heavily with modern ES Modules (import/export). It often throws the ERR_MODULE_NOT_FOUND error unless you configure it with complicated flags (like --esm).
  • tsx (The Modern Way): It stands for TypeScript Execute and is the modern replacement for ts-node.
  • Speed: tsx is built on top of esbuild, which makes it incredibly fast compared to ts-node.
  • Zero Config: It flawlessly handles both CommonJS (require) and ES Modules (import) out of the box without requiring any extra setup.
मराठी सारांश:
  • जुना ts-node बऱ्याचदा ES Modules सोबत (import/export) नीट काम करत नाही आणि ERR_MODULE_NOT_FOUND एरर देतो.
  • त्याऐवजी आपण आता tsx वापरतो. ते esbuild मुळे खूप फास्ट आहे आणि कुठल्याही एक्स्ट्रा सेटिंग शिवाय थेट TypeScript रन करते.

Q. What is `package.json`?

Concept:
  • package.json is the main configuration and metadata file for any Node.js project.
  • It acts as the "Identity Card" of the project, containing the project's name, version, author, and description.
  • It is essential for managing dependencies (the external libraries your project needs to run).
  • It is also used to define custom scripts (like npm start) and identify the main entry point of the application.
  • You can generate it automatically by running npm init -y in your terminal.
  • name & version: Crucial for identifying the project if published.
  • main: The entry point file of your application (usually index.js or app.js).
  • scripts: Custom commands you can run using npm run <script-name> (e.g., npm start or npm run dev).
  • dependencies: A list of packages required for the app to run in production (installed via npm install <pkg>).
  • devDependencies: A list of packages only needed for development and testing, like nodemon or typescript (installed via npm install -D <pkg>).
Code Example: A Sample package.json File
{
  "name": "my-node-app",
  "version": "1.0.0",
  "main": "app.js",
  "scripts": {
    "start": "node app.js",
    "dev": "nodemon app.js"
  },
  "dependencies": {
    "express": "^4.18.2"
  },
  "devDependencies": {
    "nodemon": "^3.0.1"
  }
}

Q. What is `package-lock.json`?

Concept:
  • package-lock.json is a file automatically generated by npm when a project's dependencies are installed or updated.
  • While package.json only specifies the minimum required versions of dependencies, package-lock.json records the exact versions of every single package and sub-package installed.
  • This guarantees that the exact same dependency tree is installed on every machine, ensuring perfectly reproducible builds across different environments.
  • Version Locking: It locks the exact version of every installed package and its nested dependencies. This ensures that if another developer clones the project and runs npm install, they get the exact same versions of all packages.
  • Speed: It speeds up the installation process because npm doesn't have to resolve version conflicts or fetch metadata for every package—it just reads the lock file.
  • Rule: You should ALWAYS commit package-lock.json to GitHub along with package.json. Do NOT ignore it.
मराठी सारांश:
  • package.json म्हणजे आपल्या प्रोजेक्टचे Identity Card आहे ज्यामध्ये प्रोजेक्टचे नाव आणि लागणाऱ्या packages ची यादी असते.
  • तर package-lock.json म्हणजे त्या packages चे exact versions lock करणारी फाईल आहे, जेणेकरून दुसऱ्या developer च्या मशीनवर पण सेम कोड चालेल.
  • या दोन्ही फाईल्स नेहमी GitHub वर upload कराव्यात.

Q. Dependencies vs DevDependencies

  • Dependencies:
    • These are packages required by the application to run in production.
    • Examples: Express, Mongoose.
    • Installed using: npm install <package-name>.
  • DevDependencies:
    • These are packages required ONLY during development.
    • They are NOT needed in production.
    • Examples: Testing tools (Jest) or live-reloading tools (Nodemon).
    • Installed using: npm install --save-dev <package-name> (or -D).
Code Example: Installing Dependencies
// 1. Install regular dependency (production)
npm install react

// 2. Install dev dependency (only for development)
npm install -D nodemon
मराठी सारांश:
  • Dependencies म्हणजे असे packages जे ॲप चालवण्यासाठी आवश्यक आहेत (उदा. Express).
  • आणि DevDependencies म्हणजे असे packages जे फक्त coding करताना मदत करतात, पण फायनल ॲपमध्ये त्यांची गरज नसते (उदा. Nodemon).

Q. NPM Scripts

  • NPM scripts allow you to define custom terminal commands in your package.json file.
  • Instead of typing long commands like node --watch server/app.js, you can define a script and run it using npm run <script-name>.
Code Example: Running NPM Scripts
// Inside package.json:
"scripts": {
  "start": "node server.js",
  "dev": "nodemon server.js"
}

// In terminal, run:

Chapter 2: Node.js REPL

Q. What is REPL?

Definition: Node.js REPL is an interactive command-line environment where we can read, evaluate, print the result, and repeatedly execute JavaScript code directly within the terminal.
  • R (Read): Read the user input & parse into the JavaScript code or data structure that the JS engine can understand and store in memory.
  • E (Evaluate): Take input and evaluate (the parsed input is executed by the JS engine; if it is a valid expression, the REPL computes the result).
  • P (Print): Print the result of evaluation to the console (so that we can see the output).
  • L (Loop): Loop back to read more user input (the process waits for the next input, and continues until the user exits).
मराठी:
  • REPL (Read-Evaluate-Print-Loop) हे एक interactive shell आहे जिथे आपण JavaScript code लिहून लगेच त्याची output पाहू शकतो.

Chapter 3: Global Object & globalThis

Q. Why Node.js does not have a window object?

  • In Node.js, there is no window object because Node.js runs outside the browser.
  • So it does not deal with DOM, BOM, or browser-specific APIs.
  • Instead, Node.js has a global object.
  • It is equivalent to the window in the browser but designed for a server-side environment.

Q. What is the use of the globalThis keyword?

Concept:
  • globalThis is a standard, cross-environment way to access the global object in JavaScript, introduced in ECMAScript 2020.
  • It provides a consistent way to access the global object regardless of the JavaScript environment (Browser, Node.js, Web Workers).
  • In the past, accessing the global object varied: window in Browser, global in Node.js, and self in Web Workers.
  • globalThis solves this by providing one universal name for all environments.
मराठी सारांश (globalThis):
  • पूर्वी वेगवेगळ्या environment मध्ये global object चे नाव वेगळे असायचे (उदा. browser मध्ये window, Node.js मध्ये global).
  • पण आता globalThis आल्यामुळे सर्व ठिकाणी एकच शब्द वापरता येतो.
Figure 4: globalThis is Environment-Independent
Example 1: globalThis in Browser vs Node.js
// ─── Browser Environment ───
console.log(globalThis === window);
// → true   (Because in a browser, globalThis points to window)

// ─── Node.js Environment ───
console.log(globalThis === global);
// → true   (Because in Node.js, globalThis points to global)
What happens: globalThis seamlessly adapts to whichever environment the code is running in and points to the respective global object. Output: true in both environments. ✅ Advantage: We no longer need if (typeof window !== "undefined") checks.

Q. globalThis vs Global Scope

  • globalThis refers to the global object.
  • But a variable declared with let, const, or class does NOT automatically become a property of the global object (unlike var declarations in some global contexts).
Example 2: let vs explicit property
let x = 30;
console.log(x);
// → 30

console.log(globalThis.x); 
// → undefined   (Variables declared with let have block scope and don't attach to the global object)

// But if we explicitly set it:
globalThis.x = 10;
console.log(globalThis.x);
// → 10   (Explicitly creates/accesses a property on the global object)
What happens: let variables do not attach to the global object. To store something globally, you must explicitly attach it using globalThis.propertyName.
मराठी सारांश:
  • let किंवा const ने बनवलेले variables आपोआप global object चा भाग बनत नाहीत.
  • त्यासाठी globalThis.variableName असे स्पष्टपणे लिहावे लागते.

Q. How to access a variable globally without using export and import?

  • Normally, we use export and import to share variables between files.
  • But if we want a value to be globally accessible everywhere, we can attach it to the global object using globalThis or global.
Example 3: Setting a Global Variable
globalThis.username = 'heloo_javascript';
console.log(globalThis.username);
// → 'heloo_javascript'
What happens: You can now access globalThis.username in any other module in your Node.js application without importing it. ⚠ Disadvantage: Overusing this causes polluted global scope and makes tracking state changes hard.
मराठी सारांश:
  • जर तुम्हाला एखादा variable import/export न करता सगळीकडे वापरायचा असेल,
  • तुम्ही तो globalThis ला जोडू शकता.

Q. Should we use global variables (globalThis) for everything?

  • NO. As a general application design, use them CAREFULLY.
  • Avoid unnecessarily doing things like: globalThis.user = {} or globalThis.database = {}.
  • Problems:
    • Global state can be changed from anywhere (difficult to track).
    • Can create naming conflicts.
    • Makes testing harder and creates hidden dependencies.
  • Prefer: Modules (export/import), functions, classes, or dependency injection.
  • Use Case: Only use globalThis for genuine environment-level configurations.
मराठी सारांश:
  • प्रत्येक गोष्टीसाठी global variables वापरू नयेत.
  • यामुळे code मध्ये bugs येऊ शकतात आणि testing अवघड होते.
  • शक्यतो import/export चाच वापर करा.

Q. The process Object

Concept:
  • process is a built-in Node.js global object.
  • It provides information and control related to the current running Node.js process.
  • Important point: Global variables are only available within the same Node.js process.
  • They are NOT automatically shared between different Node.js processes (i.e., if you spin up two separate servers, they don't share globals).
  • To share data between multiple processes, use: Redis, Databases, or Message Brokers.
मराठी सारांश:
  • process object आपल्याला सध्या चालू असलेल्या Node.js program ची माहिती देतो (जसे की ID, Folder Path).
  • Global variables फक्त एका process पुरतेच मर्यादित असतात.
Example 4: Using the process object
console.log(process.pid);
// → 12345   (Returns the Process ID of the currently running Node.js instance)

// ✔ corrected: console.log(process.pwd); is wrong. There is no `pwd` property. Use process.cwd() instead.
console.log(process.cwd());
// → 'D:\IMP\FULL-NODE-JS'   (Returns the Current Working Directory)
✔ `process.pwd` does not exist in Node.js. The correct function to get the current working directory is `process.cwd()`.
✔ मराठी: Node.js मध्ये `process.pwd` नसते. सध्याची directory कोणती आहे हे शोधण्यासाठी `process.cwd()` हे function वापरावे लागते.

  • Global variables are scoped to a single process, not the operating system.

  • You use the process.cwd() method.
  • This returns the absolute path of the current working directory of the Node.js process.

  • NO. This is a very common interview trap!
  • Even though you can use them anywhere without importing, they are not attached to globalThis.
  • Node.js internally wraps every file in a hidden Module Wrapper Function before execution.
  • __dirname, __filename, require, module, and exports are actually passed as local arguments to this hidden wrapper function, making them local to the current file only.
Q6. What is the exact difference between `__dirname` and `process.cwd()`?
  • __dirname: Always returns the path of the folder where the current file is located. (It is fixed).
  • process.cwd(): Always returns the path of the folder from where you ran the `node` command in the terminal. (It is dynamic).

  • __dirname फाईल कुठे आहे ते सांगते, आणि process.cwd() terminal मध्ये command कुठून चालवली ते सांगते.

Chapter 4: Module System in Node.js

Q. What is a Module System in Node.js?

Concept:
  • A module is a self-contained, reusable, and encapsulated unit of code.
  • The module system is a mechanism that allows us to divide an application into separate, independent files (modules) instead of writing everything in one large file.
  • Each module can contain related variables, functions, classes, objects, constants, and business logic.
  • A module can:
    • Keep its internal code private (Encapsulation).
    • Export functionality that other modules need.
    • Import functionality from other modules.
  • In CommonJS (the default Node.js module system), each JavaScript file is treated as a separate module, and variables/functions inside it are private by default.
  • This makes the application modular, reusable, maintainable, testable, and easier to debug.
मराठी:
  • Module म्हणजे एक स्वतंत्र फाईल ज्यामध्ये संबंधित code असतो.
  • Node.js मध्ये आपण संपूर्ण application एकाच फाईलमध्ये न लिहिता अनेक modules (files) मध्ये विभागू शकतो.

Q. Why do we need Modules?

  • Encapsulation: Keeps internal implementation private. Other modules cannot access internal variables directly unless exported.
  • Reusability: A module (like `math.js`) can be written once and reused in multiple files.
  • Better Code Organization: Related functionality is kept together (e.g., all auth logic in `auth.js`).
  • Separation of Concerns: Each module focuses on a specific responsibility (e.g., database connection vs. user operations).
  • Easier Maintenance: If there is a bug, you only need to check the specific module instead of scanning a massive single file.
  • Prevent Global Scope Pollution: Variables inside a module do not conflict with variables in another module.
  • Module Caching: Node.js caches modules after they are loaded, avoiding repeated evaluation and improving performance.
मराठी सारांश:
  • Modules मुळे code सुरक्षित राहतो (Encapsulation), पुन्हा वापरता येतो (Reusability), आणि चुका शोधायला (Debugging) सोपे जाते.
  • एकाच फाईलमध्ये सर्व code लिहिण्यापेक्षा तो वेगवेगळ्या फाईल्समध्ये विभागणे चांगले असते.

Q. What are the Types of Modules in Node.js?

  • 1. Core / Built-in Modules: Provided by Node.js itself. No need to install them. (e.g., fs, path, os, http).
  • 2. User-defined Modules: Custom modules created by the developer (e.g., math.js, auth.js).
  • 3. Third-party Modules: Packages created outside the Node.js core, commonly installed through npm (e.g., express, mongoose, lodash).
मराठी सारांश:
  • Node.js मध्ये ३ प्रकारचे modules असतात: 1) Core (जे Node.js मध्ये आधीपासून असतात), 2) User-defined (जे आपण बनवतो)
  • 3) Third-party (जे आपण npm वरून download करतो).

Q. What are the two Module Systems in Node.js?

  • Node.js supports two major JavaScript module systems: CommonJS and ES Modules (ESM).
  • CommonJS: The traditional module system in Node.js. Uses module.exports to export and require() to import.
  • ES Modules (ESM): The standard JavaScript module system (modern). Uses export to export and import to import.
मराठी सारांश:
  • Node.js मध्ये दोन प्रकारच्या module systems आहेत.
  • जुनी पद्धत CommonJS आहे जिथे आपण require वापरतो, आणि नवीन पद्धत ES Modules (ESM) आहे जिथे आपण import/export वापरतो.
Figure 7: CommonJS vs ES Modules

Q. How can we export something in CommonJS?

  • There are two common approaches to exporting logic in CommonJS.
  • 1. Assign an object to module.exports: You can wrap multiple functions inside an object and export the entire object at once.
  • 2. Assign properties individually: You can attach functions one by one using module.exports.propertyName = functionName.
IMPORTANT: module.exports is a VALUE.
  • It represents the final value exported. If you re-assign module.exports = multiply;, the previous exports are completely replaced.
Avoid Confusing: module.exports vs module.exports.property
// ─── Example 1: Assigning a Property ───
module.exports.add = add;
// The exports object now has a new property called `add`.
// Shape: { add: [Function] }

// ─── Example 2: Re-assigning the whole object ───
module.exports = add;
// The exports value IS the function directly.
// Shape: [Function]
What happens: Be very careful not to accidentally overwrite the entire module.exports object when you meant to just add a property.
मराठी सारांश:
  • CommonJS मध्ये काही export करायचे असेल तर आपण module.exports = ... वापरतो.
  • पण लक्षात ठेवा, module.exports हे एक value आहे.
  • जर तुम्ही त्याला नवीन function assign केले तर आधीचे सगळे export पुसले जातील.

Q. What is the difference between a Module and a Function?

  • Module: A larger organizational unit (a container). It is usually a single file that contains multiple related functions, variables, classes, and logic.
  • Function: A reusable piece of executable logic designed to perform a particular task. A function exists inside a module.
मराठी सारांश:
  • Module हे एक मोठे Container (डबा) असते ज्यामध्ये अनेक Functions, Variables, आणि Classes असू शकतात.
  • तर Function हे एक छोटे काम करणारे logic असते जे Module च्या आत असते.

Q. Why is the `module` object NOT Global in Node.js?

  • module is NOT a global object. Node.js provides it locally inside each CommonJS module wrapper.
  • Conceptually, Node.js wraps every CommonJS file inside an invisible function before executing it:
    (function (exports, require, module, __filename, __dirname) { /* your code */ });
  • Because module is provided as a local parameter of this wrapper function, it belongs ONLY to that module's scope.
  • This ensures scope isolation, preventing different files from polluting each other's namespaces.
मराठी सारांश:
  • module हा global object नाही.
  • Node.js प्रत्येक फाईलला एका अदृश्य function च्या आत wrap करते, आणि module त्या function चा parameter असतो.
  • यामुळे प्रत्येक फाईलचे variables सुरक्षित राहतात.

Q. How do ESM modules handle the `module` object?

  • ES Modules don't have the CommonJS module object or __dirname / __filename variables.
  • ESM is a completely different module mechanism.
  • If you need metadata about the current module in ESM (like the file path), you must use the import.meta object instead.
✔ Corrected: ESM is itself a module system. It uses a different mechanism (`import`/`export` and `import.meta`).
✔ मराठी: ESM ही स्वतः एक वेगळी module system आहे, त्यामुळे त्यात CommonJS प्रमाणे `module` object नसतो; त्याऐवजी `import.meta` वापरले जाते.

Interview Questions (Detailed)

Q1. What is the difference between `module.exports` and `exports`?
  • module.exports is the actual object that gets returned by a require() call.
  • exports is initially just a shorthand reference (pointer) to module.exports.
  • If you directly assign a new value to exports (like exports = add;), you break the reference, and it will NOT export anything. Always use module.exports = ... or exports.property = ....
Q2. Are variables in a module automatically available in the global scope?
  • No. Variables declared inside a Node.js module are private to that module due to the CommonJS wrapper function.
  • To make them accessible outside, they must be explicitly added to module.exports or attached to globalThis.
Q3. What happens if I `require()` the same module in two different files? Does it execute twice?
  • No. Node.js caches modules after the first time they are loaded.
  • When the second file calls require(), Node.js returns the cached module.exports object instead of re-executing the entire file. This improves performance.
Q4. How do you find the directory name of the current file in CommonJS vs ESM?
  • In CommonJS: You use the injected variable __dirname.
  • In ES Modules (ESM): __dirname is not defined. You have to derive it using import.meta.url and the path/url core modules.
मराठी सारांश:
  • Modules च्या interview मध्ये module.exports विरुद्ध exports हा सर्वात महत्त्वाचा प्रश्न आहे.
  • तसेच Node.js modules cache करते (म्हणजेच फाईल पुन्हा पुन्हा रन करत नाही) आणि variables private ठेवते हे लक्षात ठेवणे गरजेचे आहे.

Chapter 5: require() vs import

Q. What is require()?

Concept:
  • require() is a synchronous, runtime-oriented CommonJS (CJS) module-loading mechanism.
  • It is used to load built-in Node.js modules, third-party packages, or local custom modules.
  • It returns the value exported by module.exports.
  • It is NOT a standard JavaScript language function; it belongs exclusively to the CommonJS environment in Node.js.
  • CommonJS require() is synchronous. The execution waits for require() to finish loading the module before continuing to the next line.
  • Node.js supports two major module systems:
    • CommonJS: require() + module.exports
    • ES Modules (ESM): import + export
मराठी सारांश:
  • require() हे CommonJS चे function आहे जे दुसऱ्या फाईलचा (module) code आपल्या फाईलमध्ये आणण्यासाठी वापरले जाते.
  • हे synchronous आहे, म्हणजे जोपर्यंत फाईल load होत नाही तोपर्यंत पुढचा code रन होत नाही.

Q. How does require() resolve and load a module? (Module Cache)

  • When Node sees require("./math"), it conceptually does the following:
  • 1. Resolve Path: Finds where the file is actually located.
  • 2. Check Cache: Node.js checks if this module was already loaded before.
    • If YES (already cached) -> Returns the cached module.exports immediately.
    • If NO (first time) -> Loads the module -> Executes the module -> Caches the exported value -> Returns it.
  • Because of this caching, if you require("./math") multiple times in different files, the math.js file is evaluated only ONCE. Subsequent calls return the cached module.

  • Node.js एकदा load केलेली फाईल cache (लक्षात) ठेवते.
  • म्हणजे जर तुम्ही math.js फाईल २ वेळा require केली, तरी ती फक्त पहिल्यांदाच रन होईल, दुसऱ्या वेळी cache मधील result दिला जाईल.

  • In CommonJS, it commonly allows you to drop the extension: require("./math") instead of require("./math.js"). Node automatically infers the .js extension.
  • IMPORTANT: Do NOT generalize this behavior to ESM. Relative/absolute imports in ESM generally require explicit file extensions (like import math from "./math.js").

  • require('./math')), पण ESM मध्ये import करताना .js लिहिणे बंधनकारक आहे.

Q. What is import? (ES Modules)

  • import belongs to ES Modules (ESM).
  • ESM is the standardized JavaScript module system.
  • ESM uses import to load modules and export (or export default) to expose them.
Example 1: ESM Exports & Imports
// math.js (Exporting)
export function add(a, b) { return a + b; }                // Named Export
export default function subtract(a, b) { return a - b; }   // Default Export

// app.js (Importing)
import subtract from "./math.js";           // Importing Default (no curly braces)
import { add } from "./math.js";            // Importing Named (needs curly braces)
Memory Trick: Named Export -> Needs { } braces when importing.
Default Export -> Does NOT need { } braces when importing.
मराठी सारांश:
  • ESM ही नवीन पद्धत आहे.
  • यात Named export ला { } लागतात आणि Default export ला लागत नाहीत.

Q. How to enable ESM in Node.js?

  • Method 1: Add "type": "module" in your package.json file. All .js files will now be treated as ESM.
  • Method 2: Use the .mjs file extension. (Node treats .mjs files as ESM regardless of package.json).
  • If you need explicitly CommonJS, you can use the .cjs file extension.
मराठी सारांश:
  • Node.js मध्ये ESM वापरण्यासाठी एकतर package.json मध्ये "type": "module" लिहा, किंवा फाईलचे नाव app.mjs असे ठेवा.

Q. require() vs static import vs dynamic import() (Detailed Differences)

  • 1. require():
    • Belongs to CommonJS (CJS).
    • Synchronous: It blocks execution until the module is fully loaded.
    • Runtime-oriented: It evaluates dependencies at runtime (you can conditionally require modules inside an if block, though it's still synchronous).
    • Harder for bundlers to analyze statically (poor tree-shaking support).
  • 2. Static import:
    • Belongs to ES Modules (ESM).
    • Statically Analyzed: Dependencies are resolved and linked before the code actually runs.
    • Must be placed at the top level of the file (you cannot put a static import inside an if statement).
    • Very strong static analysis, making it highly Tree-Shaking friendly (dead code elimination).
  • 3. Dynamic import():
    • Belongs to ES Modules (ESM), but operates like a function.
    • Asynchronous: It returns a Promise.
    • Evaluated at runtime. Perfect for Lazy Loading, conditional loading, and code splitting (loading heavy modules only when actually needed).
Code Example: The 3 Approaches
// 1. require() (CommonJS - Synchronous)
const fs = require('fs');
const data = fs.readFileSync('./file.txt');

// 2. Static import (ESM - Must be at top-level)
import { readFile } from 'fs/promises';
const data = await readFile('./file.txt');

// 3. Dynamic import() (ESM - Asynchronous & Conditional)
if (userClicksDownloadPDF) {
    // pdf-generator is a heavy package, so we load it ONLY if needed
    const pdfLib = await import('pdf-generator');
    pdfLib.generate();
}
What happens: The dynamic import() statement prevents the heavy pdf-generator package from loading into memory when the server starts. It only loads when a specific condition is met, saving RAM and startup time.

मराठी सारांश (Detailed):
  • 1. require():
    • ही CommonJS ची जुनी पद्धत आहे.
    • ही Synchronous असते, म्हणजे जोपर्यंत फाईल पूर्ण लोड होत नाही, तोपर्यंत पुढचा कोड थांबून राहतो (रन होत नाही).
  • 2. static import:
    • ही ES Modules ची नवीन पद्धत आहे.
    • ही नेहमी फाईलच्या अगदी वर (top-level) लिहावी लागते.
    • यामुळे bundlers (उदा. Webpack) ला न वापरलेला फालतू कोड (dead code) सहज ओळखून काढायला मदत होते. यालाच Tree Shaking म्हणतात.
  • 3. dynamic import():
    • ही Asynchronous असते आणि Promise return करते.
    • जेव्हा आपल्याला एखादी मोठी फाईल नेहमी नको असते, तर फक्त विशिष्ट वेळी (उदा. एखाद्या button वर click केल्यावर) लोड करायची असते, तेव्हा याचा वापर होतो.
    • यामुळे सुरुवातीला मेमरी वाचते. या पद्धतीला Lazy Loading म्हणतात.

Q. Tree Shaking vs Minification

  • Tree Shaking: A build-time optimization technique that uses static analysis to safely remove unused code from the final JavaScript bundle. (Question: "Do we need this code?")
  • Minification: A process that makes the required code smaller by shrinking/removing unnecessary characters like spaces, comments, and long variable names. (Question: "Can we make the required code smaller?")
  • Memory Trick: Tree Shaking -> REMOVES unnecessary code. Minification -> SHRINKS remaining code.
  • Important: Tree shaking is NOT performed by Node.js automatically at runtime. It is performed by compatible build tools/bundlers (like Webpack or Vite) during the build process.
  • ESM (import/export) is tree-shaking friendly because its static structure allows tools to confidently know which exports are used and which are not. CommonJS (require) makes this very hard because imports are dynamic at runtime.
मराठी सारांश:
  • Tree Shaking म्हणजे न वापरलेला फालतू code काढून टाकणे (ESM मुळे हे शक्य होते).
  • आणि Minification म्हणजे आवश्यक असलेला code ची size कमी करणे (spaces आणि comments काढून).
  • Node.js स्वतः Tree shaking करत नाही, ते Bundlers करतात.

Q. The Module Wrapper Function (IIFE)

Concept:
  • Before Node.js executes the code of a CommonJS module, it internally wraps that module's code inside a hidden function.
  • This invisible function is known as the Module Wrapper Function.
  • It behaves exactly like an IIFE (Immediately Invoked Function Expression) in standard JavaScript.
  • Why is it needed?
    • Private Module Scope (Encapsulation): Variables declared in one file don't automatically leak into the global scope and crash variables in other files.
    • Dependency Injection: It provides 5 important variables (exports, require, module, __filename, __dirname) into the module's scope.
  • These 5 variables look like global variables, but they are actually local to the specific module because they are passed as parameters to this hidden function.
  • Note: This wrapper mechanism is strictly for CommonJS. ES Modules (ESM) do not use this wrapper function.
Code Example: Conceptual View of the Wrapper
// 1. When you write this code in your app.js:
const username = "Vishal";
console.log(__filename);
module.exports = username;

// 2. Node.js conceptually wraps it like this before executing:
(function (exports, require, module, __filename, __dirname) {
    
    // --- YOUR CODE STARTS HERE ---
    const username = "Vishal";
    console.log(__filename);
    module.exports = username;
    // --- YOUR CODE ENDS HERE ---

}); // <-- and then immediately invokes it, passing the 5 arguments!
What happens: Because your code is inside a function, const username becomes a local variable of that function. It does not pollute the global Node.js environment!
Figure 10: How Node.js keeps module scope private
मराठी सारांश (Detailed):
  • Node.js कोणताही CommonJS फाईल रन करण्यापूर्वी त्याला एका function मध्ये (Wrapper Function) गुंडाळते.
  • यामुळे त्या फाईलचे variables सुरक्षित (private) राहतात आणि इतर फाईल्समध्ये मिसळत नाहीत.
  • या wrapper मुळेच आपल्याला require आणि __dirname सारख्या गोष्टी वापरता येतात ज्या फक्त त्या फाईल पुरत्या मर्यादित असतात.
  • महत्त्वाची नोंद: ही Wrapper Function पद्धत फक्त CommonJS मध्येच असते. ES Modules (ESM) मध्ये आपण याचा वापर करू शकत नाही.

Q. The 5 Parameters of the Wrapper

  • 1. exports: A shortcut reference to module.exports. (You can do exports.add = add, but you cannot do exports = add to completely overwrite it).
  • 2. require: A function used to import other CommonJS modules.
  • 3. module: An object representing the current module. The most important property is module.exports, which determines what gets exported.
  • 4. __filename: The absolute path to the current module file.
  • 5. __dirname: The absolute path to the directory containing the current module.
मराठी सारांश (Detailed):
  • Wrapper function मुळे फाईलला ५ गोष्टी मिळतात: exports, require, module, __filename, __dirname.
  • हे दिसायला global वाटतात, पण ते फक्त त्याच फाईलसाठी (local) उपलब्ध असतात.
  • तसेच या ५ गोष्टी आपण ES Modules (ESM) मध्ये वापरू शकत नाही (उदा. ESM मध्ये require किंवा __dirname चालत नाही).

Q. Practical Equivalents: CommonJS vs ES Modules (ESM)

Concept:
  • Because ESM does not use the Module Wrapper Function, it does not have access to require, module.exports, __dirname, or __filename.
  • If you are converting a CommonJS project to an ESM project, you must manually recreate these missing variables using ESM's import.meta.url.
  • You also need to change how you export and import functions, and how you load JSON files.
  • 1. Importing & Exporting:
    • In CommonJS, you use require() for importing and module.exports for exporting.
    • In ESM, you must replace require() with import.
    • For exporting in ESM, you must replace module.exports with export default or named export.
  • 2. Getting __dirname & __filename:
    • In CommonJS, these are automatically available via the Module Wrapper Function.
    • In ESM, the wrapper function does not exist, so these variables do not exist.
    • You must manually calculate them using fileURLToPath from the url core module and dirname from the path core module.
  • 3. Importing JSON files:
    • In CommonJS, importing a JSON file is as simple as require('./data.json'). Node automatically parses it into an object.
    • In ESM, using a normal import for JSON will throw an error.
    • You must use a special Import Assertion to tell Node.js it is a JSON file: import data from './data.json' with { type: "json" };
Figure 11: Side-by-Side Comparison of CJS vs ESM Syntax
Code Example: How to recreate __dirname in ESM
// ESM DOES NOT have __dirname. You must create it manually like this:

import path from 'path';
import { fileURLToPath } from 'url';

// 1. Get the current file's absolute path using import.meta.url
const __filename = fileURLToPath(import.meta.url);

// 2. Extract the directory name from the file path
const __dirname = path.dirname(__filename);

console.log("Directory path is:", __dirname);
मराठी सारांश (Practical Migration Guide):
  • 1. __dirname आणि __filename: ESM मध्ये हे नसतात. तुम्हाला import.meta.url आणि fileURLToPath वापरून ते मॅन्युअली काढावे लागतात (वरील कोड प्रमाणे).
  • 2. JSON फाईल्स: JSON फाईल्स import करताना ESM मध्ये with { type: "json" } असा खास उल्लेख करावा लागतो.
  • 3. फाईल Extension: CommonJS मध्ये फाईल import करताना require('./app') चालत असे. पण ESM मध्ये फाईलचे पूर्ण नाव extension सहित (उदा. import './app.js') लिहिणे बंधनकारक आहे.
  • 4. Exports: module.exports च्या जागी आता export किंवा export default वापरावे लागते.
  • 5. Top-level Import: require() आपण कोणत्याही if block मध्ये वापरू शकत होतो, पण import हे नेहमी फाईलच्या सर्वात वर (Top-level) लिहावे लागते.

Chapter 6: The process Object

Q. What is process in Node.js?

Concept:
  • process is a global object provided built-in by Node.js.
  • It gives you vital information about the currently running Node.js process (such as memory usage, process ID, and environment variables).
  • It also gives you control over the process (such as the ability to exit the process manually).
  • Since process is a global object, we do not need to import it (i.e. no require('process') is needed).
  • The process object provides the following key capabilities:
    • Process Information: Get details about the running OS and Node instance (e.g., process.pid, process.platform, process.version).
    • Environment Information: Access system environment variables or configuration data using process.env.
    • Command-line Arguments: Read inputs passed from the terminal when starting the script using process.argv.
    • Memory Usage: Check how much RAM the Node.js process is consuming using process.memoryUsage().
    • Process Control: Manually terminate the application using process.exit() or get the current working directory using process.cwd().
    • Events & Signals: Listen for system events like unhandled errors (uncaughtException) or termination signals (SIGINT).
  • Note on Environment Variables (dotenv):
    • To load custom configuration variables (like API Keys or Database Passwords), we use a package called dotenv.
    • The dotenv package reads a .env file in your project and automatically loads its contents into the process.env object.
मराठी सारांश:
  • process हा Node.js चा एक built-in global object आहे.
  • हा object सध्या चालू असलेल्या Node.js program बद्दल महत्त्वाची माहिती देतो (उदा. Process ID, OS ची माहिती, आणि RAM किती वापरली जात आहे).
  • याचा वापर करून आपण terminal मधून दिलेले inputs (command-line arguments) वाचू शकतो.
  • तसेच, dotenv package च्या मदतीने आपण .env फाईलमधील passwords आणि keys या process.env मध्ये लोड करू शकतो.
  • या object मुळे आपण process ला मध्येच थांबवू (exit) किंवा पूर्णपणे control करू शकतो.

Q. Important Process Properties (pid, platform, arch, versions)

  • process.pid: Returns the Process ID (PID) of the currently running Node.js process. 
    console.log(process.pid); // 10952
  • process.ppid: Returns the Process ID of the parent process that started the current Node.js process. 
    console.log(process.ppid); // 8421
  • process.platform: Returns the operating system platform. Useful for OS-specific code. 
    console.log(process.platform); // 'win32' (Windows), 'linux', or 'darwin' (macOS)
  • process.arch: Returns the CPU architecture. 
    console.log(process.arch); // 'x64', 'arm64', or 'ia32'
  • process.version: Returns the version of the running Node.js. 
    console.log(process.version); // 'v20.9.0'
  • process.versions: Returns an object containing version info for Node.js and its internal dependencies (like v8, openssl, zlib). 
    console.log(process.versions.v8); // '11.3.244.8-node.16'
मराठी सारांश:
  • process.pid आणि process.ppid ने अनुक्रमे सध्याच्या आणि parent process चा ID मिळतो.
  • process.platform आणि process.arch ने आपला OS (उदा. Windows/Linux) आणि CPU ची माहिती मिळते, ज्याचा उपयोग OS नुसार कोड चालवण्यासाठी होतो.
  • process.version मुळे Node.js चे सध्याचे version कळते.
  • process.versions मुळे Node.js सोबत येणाऱ्या इतर dependencies (जसे की v8 engine) चे व्हर्जन्स मिळतात.

Q. Command-line Arguments: argv vs execArgv vs argv0

  • process.argv: An array containing the command-line arguments passed when launching the Node.js process.
    • argv[0] = Node.js executable absolute path.
    • argv[1] = Path of the JavaScript file being executed.
    • argv[2], argv[3]... = User-provided arguments.

  • process.argv0: Contains the original value of argv[0] passed when the Node.js process started. 
    console.log(process.argv0); // 'node'
  • process.execArgv: Contains the command-line arguments passed directly to the Node.js executable (like --inspect), NOT the normal application arguments. 
    // Command: node --inspect app.js
console.log(process.execArgv); // ['--inspect']

Q. process.cwd() vs __dirname

  • process.cwd(): Returns the Current Working Directory. It tells us: "From which directory was the Node.js process launched?" 
    console.log(process.cwd()); // e.g. 'D:\MyProject'
  • __dirname (CommonJS): Returns the absolute directory path containing the current JavaScript file being executed. 
    console.log(__dirname); // e.g. 'D:\MyProject\src'

    • process.cwd() points to the root folder (where the terminal is).
    • __dirname inside app.js points to the src folder (where the file is).
मराठी सारांश:
  • process.cwd() म्हणजे तुम्ही ज्या folder मधून terminal वर node command टाकली आहे तो folder.
  • __dirname म्हणजे तुमची JavaScript फाईल ज्या फोल्डरमध्ये सेव्ह केलेली आहे तो folder.
  • जर तुम्ही एका फोल्डरमधून दुसऱ्या फोल्डरमधील फाईल रन केली, तर हे दोन्ही paths वेगवेगळे असू शकतात.

Q. Memory & Uptime

Q. Process Control (exit, exitCode, kill)

  • process.exit(code): Immediately terminates the Node.js process. Code 0 means success, non-zero (like 1) indicates failure/error. Code after process.exit() will never run. 
    process.exit(1); // Exits with an error
  • process.exitCode: Specifies the exit code that Node will use when the process exits naturally. Best practice is to set process.exitCode = 1; instead of forcing an abrupt process.exit(1) if you want to let pending operations finish first.
  • process.kill(pid, signal): Sends a signal to a process. It does NOT necessarily mean "force kill". It just sends a signal (like SIGTERM) to the given process ID. 
    process.kill(process.pid, 'SIGTERM');
  • process.abort(): Immediately terminates the process and generates a core dump (useful for low-level debugging).
मराठी सारांश:
  • process.exit() ने program तात्काळ बंद होतो आणि त्यापुढील कोणताही कोड चालत नाही.
  • जर तुम्हाला program ची उरलेली कामे संपवून मगच error code देऊन बंद करायचा असेल, तर process.exitCode = 1 वापरणे जास्त सुरक्षित असते.
  • process.kill() ने एखाद्या process ला signal पाठवता येतो (उदा. SIGTERM), तर process.abort() मुळे process लगेच crash होते.

Q. Process Events & Signals

  • exit: Emitted when the Node.js process is about to exit. Only synchronous code can be run here. Async code won't keep the process alive. 
    process.on('exit', (code) => { console.log(`Exiting with code: ${code}`); });
  • beforeExit: Emitted when Node.js has no more work scheduled on the event loop. You CAN schedule more asynchronous work here to keep the process alive. 
    process.on('beforeExit', () => { console.log('Event loop is empty.'); });
  • uncaughtException: Emitted when an exception is not caught and reaches the event loop. In production, log the error and do a graceful restart. Do not try to blindly keep the corrupted app running! 
    process.on('uncaughtException', (err) => { console.error('Uncaught Error:', err); process.exit(1); });
  • unhandledRejection: Emitted when a Promise is rejected and there is no .catch() handler. 
    process.on('unhandledRejection', (reason) => { console.error('Unhandled Promise Rejection:', reason); });
  • SIGINT: Signal generated when the user presses Ctrl + C in the terminal. 
    process.on('SIGINT', () => { console.log('Ctrl+C pressed!'); process.exit(0); });
  • SIGTERM: Termination signal sent by OS or Docker to request a graceful shutdown. 
    process.on('SIGTERM', () => { console.log('SIGTERM received. Shutting down...'); });
मराठी सारांश:
  • exit आणि beforeExit मुळे प्रोग्राम पूर्णपणे बंद होण्याआधी काही शेवटची कामे (उदा. logs सेव्ह करणे) करता येतात.
  • uncaughtException आणि unhandledRejection मुळे अनपेक्षित errors पकडता येतात जेणेकरून application लगेच क्रॅश होऊ नये.
  • SIGINT (Ctrl+C) आणि SIGTERM (OS termination) या signals चा वापर सर्व्हर Gracefully बंद करण्यासाठी होतो.

Q. What is Graceful Shutdown?

Definition: Graceful shutdown means properly closing resources (like database connections and active HTTP requests) before terminating the Node.js process upon receiving a termination signal like SIGTERM.
Step-by-Step Flow:
  1. Receive the termination signal (SIGTERM).
  2. Stop accepting new incoming HTTP requests (e.g., server.close()).
  3. Wait for currently active requests to finish processing.
  4. Close the Database connections cleanly.
  5. Close any open file resources or streams.
  6. Finally, call process.exit(0) to safely terminate the process.
Example Implementation: 
process.on('SIGTERM', () => {
  console.log('SIGTERM received. Shutting down gracefully...');
  
  // 1. Stop accepting new requests
  server.close(() => {
    console.log('HTTP server closed.');
    
    // 2. Close DB connections
    mongoose.connection.close(false, () => {
      console.log('MongoDB connection closed.');
      
      // 3. Exit safely
      process.exit(0);
    });
  });
});
मराठी सारांश:
  • Graceful Shutdown म्हणजे अचानक program बंद न करता, सर्व database connections आणि सुरु असलेल्या requests नीट बंद करून मगच process थांबवणे.
  • यासाठी SIGTERM signal चा वापर होतो.

Q. Process Scheduling & IPC

  • process.nextTick(): Schedules a callback to run immediately after the current operation completes, but before the event loop continues to the next phase (e.g. before timers or I/O callbacks). Overusing it recursively can block the event loop. 
    process.nextTick(() => console.log('Runs before setTimeout'));
  • process.send(): Used for Inter-Process Communication (IPC). Allows a Node.js child process to send messages to its parent process. 
    process.send({ hello: 'parent' });
  • process.connected: Indicates whether the current child process still has an active IPC connection to its parent.
मराठी सारांश:
  • process.nextTick() callback ला सर्वात जास्त Priority असते, ते इतर सर्व asynchronous कामांच्या (उदा. setTimeout) आधी रन होते. याचा जास्त वापर केल्यास Event Loop ब्लॉक होऊ शकतो.
  • process.send() चा वापर Parent आणि Child process मध्ये messages पाठवण्यासाठी (Inter-Process Communication) होतो.

Q. What is the path Module?

  • The path module provides utilities for working with file and directory paths.
  • It helps us to create, analyze, transform, and manipulate file system paths.
  • It provides utilities such as join(), resolve(), parse(), basename(), dirname(), extname(), normalize(), and relative().
  • It is a built-in module, so we just import it like this:
    const path = require('node:path'); (CommonJS)
    import path from 'node:path'; (ESM)
मराठी सारांश:
  • path module चा वापर फाईलचे आणि फोल्डरचे paths (पत्ता) योग्य प्रकारे हाताळण्यासाठी होतो.

Q. Why do you need the path module?

  • Different Operating Systems use different path separators.
  • Windows: Uses backslashes \ (e.g., C:\Users\Vishal\project\app.js).
  • Linux/macOS: Uses forward slashes / (e.g., /Users/Vishal/project/app.js).
  • If we create paths manually using simple string concatenation, our code becomes OS-dependent and might break on another machine.
  • The path module automatically handles platform-specific path differences, making path-related code perfectly portable across Windows, Linux, and macOS.
मराठी सारांश:
  • Windows मध्ये path साठी \ वापरतात तर Linux/Mac मध्ये / वापरतात.
  • आपण जर स्वतः string जोडून path बनवला तर तो दुसऱ्या OS वर चालणार नाही.
  • path module ही समस्या सोडवते.

Q. CommonJS Module Variables: __dirname vs __filename

  • __dirname: Represents the absolute path of the directory containing the current CommonJS module. It contains the drive and directory name (without the file name).

Q. Important Methods of the path Module

  • 1. path.parse(): Breaks a path into an object with properties: root, dir, base, ext, name.
  • 2. path.format(): Does the exact reverse of path.parse(). Takes an object and constructs a path string.
  • 3. path.join(): Joins multiple segments into a single path. It handles separators correctly for the current platform (unlike simple string concatenation).
  • 4. path.resolve(): Resolves a sequence of path segments into an absolute path (always returns a full absolute path from root).
  • 5. path.extname(): Returns the extension of the file path (e.g., .txt, .js). Returns empty string if no extension exists.
  • 6. path.basename(): Returns the last portion of a path (usually the file name). You can pass a second argument to remove the extension (e.g., path.basename('abc/ex.pdf', '.pdf') returns ex).
  • 7. path.dirname(): Returns the directory portion of the path (similar to __dirname).
  • 8. path.sep: Returns the platform-specific path separator (\ on Windows, / on POSIX).
  • 9. path.delimiter: Returns the platform-specific delimiter used to separate multiple paths in a list (like in the PATH environment variable). ; on Windows, : on POSIX.
  • 10. path.isAbsolute(): Checks whether a path is absolute or relative. Returns true or false.
  • 11. path.relative(from, to): Returns the relative path from one location to another.
  • 12. path.normalize(): Resolves unnecessary . (current dir), .. (parent dir), and repeated separators where appropriate.
  • 13. path.toNamespacedPath(): Converts a path to a Windows-specific namespace path when applicable. Mainly useful for Windows path handling compatibility.
Code Example: Using path methods
const path = require('node:path');

console.log(path.extname('vishal.txt')); 
// → '.txt'

console.log(path.basename('/users/hi/abc.txt', '.txt')); 
// → 'abc'

console.log(path.join('users', 'hi', 'abc.txt')); 
// → 'users\hi\abc.txt' (on Windows)

console.log(path.resolve('abc', 'vishal.js')); 
// → 'D:\IMP\FULL-NODE-JS\1-Basic\inbultModels\abc\vishal.js' (Absolute Path)

console.log(path.normalize('users//hi/../data')); 
// → 'users\data' (Removes extra slashes and resolves '..')
✔ `path.sep` separates parts of ONE path. `path.delimiter` separates MULTIPLE paths in a list.

Chapter 8: The OS Module

Q. What is the OS module in Node.js?

Definition:
  • The os module is a built-in (core) Node.js module that provides a set of operating system-related utility methods and properties.
  • It allows a Node.js application to directly interact with and query the underlying OS on which it is running — such as Windows, Linux, or macOS.
  • It is primarily used for system monitoring, diagnostics, and writing OS-aware application logic (e.g., using os.platform() to change behavior on Windows vs Linux).
  • Recommended Import: const os = require("node:os"); — using the node: prefix explicitly tells Node.js to load a built-in module, preventing accidental collision with a third-party npm package of the same name.
  • It allows us to get information about: CPU, Memory (RAM), Hostname, Network Interfaces, User Information, System Uptime, Temp Directory, and OS Version.
  • Since it is a core module, no npm installation is required. It ships with every Node.js installation.
मराठी सारांश:
  • os (Operating System) module चा वापर करून आपण ज्या कम्प्युटरवर Node.js app चालू आहे, त्या कम्प्युटरची संपूर्ण माहिती काढू शकतो (RAM, CPU, OS Version इ.).
  • हे Node.js मध्ये आधीपासूनच बिल्ट-इन असते, त्यासाठी npm install ची आवश्यकता नसते.
  • हे खूपसे system monitoring tools, DevOps scripts, आणि cross-platform apps मध्ये वापरले जाते.

Q. Important OS Module Methods (Memory & CPU)

  • os.totalmem():
    • Returns the total amount of system memory (RAM) in bytes.
    • To convert to GB: (os.totalmem() / 1024 / 1024 / 1024).toFixed(2)
  • os.freemem():
    • Returns the currently available (free/unused) system memory in bytes.
    • Useful for detecting memory pressure in a running application.
  • os.cpus():
    • Returns an array of objects. Each object represents one logical CPU core and contains: model, speed (MHz), and times (user/sys/idle ticks).
    • To get the count of CPU cores: os.cpus().length
    • This is critical for the cluster module where you spawn one worker per CPU core.
  • os.arch(): Returns the CPU architecture string (e.g., 'x64', 'arm64', 'ia32').
  • os.endianness(): Returns CPU byte order — 'LE' (Little Endian, most modern CPUs) or 'BE' (Big Endian).
  • Code Example: 
    const os = require('node:os');

console.log('Total RAM:', (os.totalmem() / 1024 / 1024 / 1024).toFixed(2) + ' GB');
console.log('Free RAM: ', (os.freemem() / 1024 / 1024 / 1024).toFixed(2) + ' GB');
console.log('CPU Cores:', os.cpus().length);
console.log('CPU Model:', os.cpus()[0].model);
console.log('CPU Arch: ', os.arch());
मराठी सारांश (Memory & CPU):
  • os.totalmem() आणि os.freemem() कम्प्युटरची एकूण आणि शिल्लक RAM bytes मध्ये देतात. GB मध्ये बघायला 1024 ने तीनदा भागावे लागते.
  • os.cpus() एक array देतो जिथे प्रत्येक CPU core ची माहिती (model, speed) असते. .length वापरून total cores मिळतात.
  • Cluster module मध्ये प्रत्येक CPU core साठी एक worker process तयार करण्यासाठी os.cpus().length वापरतात.

Q. OS Identity & User Info

  • os.platform(): Returns a short OS platform identifier string. Values: 'win32' (Windows), 'linux' (Linux), 'darwin' (macOS).
  • os.type(): Returns the full OS name as reported by the kernel. Values: 'Windows_NT', 'Linux', 'Darwin'.
  • os.release(): Returns the OS kernel release version string (e.g., '10.0.19045' on Windows 10).
  • os.version(): Returns a more human-readable, detailed OS version string (e.g., 'Windows 10 Enterprise').
  • os.hostname(): Returns the hostname (computer name) of the machine as it appears on the local network.
  • os.userInfo():
    • Returns an object with details about the currently logged-in user.

    • Optional argument: os.userInfo({ encoding: 'utf8' }) — specifies the character encoding for output strings.
  • Code Example: 
    const os = require('node:os');

console.log('Platform:  ', os.platform());  // 'win32'
console.log('OS Type:   ', os.type());      // 'Windows_NT'
console.log('OS Release:', os.release());   // '10.0.19045'
console.log('OS Version:', os.version());   // 'Windows 10 Enterprise'
console.log('Hostname:  ', os.hostname());  // 'DESKTOP-ABC123'
console.log('User Info: ', os.userInfo());  
// { username: 'Vishal', homedir: 'C:\\Users\\Vishal', shell: null, ... }
मराठी सारांश (OS Identity):
  • os.platform() short code देतो जसे 'win32' किंवा 'linux'. हा cross-platform code लिहिताना if/else मध्ये वापरतात.
  • os.type() पूर्ण OS नाव देतो जसे 'Windows_NT' किंवा 'Linux'.

Q. What is the fs module in Node.js?

Definition:
  • fs stands for File System. It is a built-in core Node.js module that provides a comprehensive set of APIs to interact with the underlying computer's file system.
  • It allows Node.js applications to read, write, update, delete, rename, copy, and manage files and directories on disk.
  • We can also work with File metadata (size, creation time, permissions) and Streams for handling large files efficiently.
  • Since it is a core module, no npm installation is required. Import: const fs = require("node:fs");
  • The fs module provides three main API styles:
    • 1. Synchronous APIs (e.g., readFileSync): Blocks the entire JavaScript thread until the operation finishes. Simple but should NOT be used in server applications for every request.
    • 2. Asynchronous Callback APIs (e.g., readFile): Does NOT block the main thread. Accepts a callback (err, data) => {} that is called when the operation is done.
    • 3. Promise-based APIs (e.g., require('node:fs/promises')): The modern recommended approach. Allows use of async/await for cleaner, readable code.
  • Code Example: 3 Ways to Read a File 
    // 1. Synchronous (Blocks thread)

console.log(dataSync);

// 2. Asynchronous Callback (Non-blocking)
fs.readFile('hello.txt', 'utf-8', (err, dataAsync) => {
    if (err) throw err;
    console.log(dataAsync);
});

// 3. Promise-based (Modern async/await)
const fsp = require('node:fs/promises');
async function readFilePro() {
    const data = await fsp.readFile('hello.txt', 'utf-8');
    console.log(data);
}
readFilePro();

  • यात तीन प्रकारच्या APIs आहेत: Synchronous (थांबून), Asynchronous Callback (background मध्ये + callback), आणि Promise-based (async/await सह modern approach).
  • Server applications मध्ये नेहमी Asynchronous किंवा Promise-based APIs वापरावेत, Synchronous कधीही नको.

Q. Synchronous vs Asynchronous (The "Parallel" Misconception)

  • Important Interview Point: Many people incorrectly say "Asynchronous fs tasks run in parallel".
  • The Reality: Asynchronous operations don't strictly run "in parallel" in JavaScript's single thread; rather, they are Non-Blocking. Node.js offloads the file operation to the OS, allowing the JavaScript thread to continue executing other code while the I/O operation happens in the background.
  • In server applications, Synchronous methods should be avoided for frequent requests because they block the event loop, delaying other users' requests.
मराठी सारांश (Sync vs Async):
  • Asynchronous म्हणजे सगळी कामे एकाच वेळी (parallel) होतात असे नाही. याचा खरा अर्थ म्हणजे Node.js फाईलचे काम OS ला सोपवतो आणि स्वतः पुढच्या code वर काम करायला मोकळा होतो (Non-blocking).
  • Synchronous methods server मध्ये वापरल्यास संपूर्ण event loop block होतो, त्यामुळे इतर users ला वाट पाहावी लागते.
  • Server applications मध्ये नेहमी Asynchronous पद्धत वापरावी.

Q. Why does readFileSync return a Buffer instead of a string?

  • Files internally contain raw bytes.
  • When no encoding is specified (e.g., fs.readFileSync('hello.txt')), Node.js gives us those raw bytes as a Buffer.
  • To get a readable string, you must either specify the encoding: fs.readFileSync('hello.txt', 'utf-8'), OR call .toString() on the buffer.

  • त्याला readable string बनवण्यासाठी 'utf-8' encoding द्यावी लागते: fs.readFileSync('hello.txt', 'utf-8')
  • किंवा Buffer वर .toString() call करता येते: buffer.toString('utf-8')

Important Attributes (Options) in FS Module

Concept:
  • Many fs methods accept an options object to modify their default strict behavior.
  • These attributes (like recursive, force, encoding) are essential for handling real-world file system scenarios safely and efficiently.
  • 1. recursive: true (Used in mkdir and rm):
    • When creating a folder (fs.mkdirSync): Automatically creates all missing parent folders instead of throwing an error.
    • When deleting a folder (fs.rmSync): Automatically deletes all files and nested folders inside the target folder before deleting the folder itself (like Shift+Delete).
  • 2. force: true (Used in rm):
    • When deleting a file or folder (fs.rmSync): Ignores exceptions if the file or folder does not exist (prevents the app from crashing with an ENOENT error).
  • 3. withFileTypes: true (Used in readdir):
    • By default, readdirSync returns an array of string names.
    • With this option, it returns an array of fs.Dirent objects, allowing you to easily check if an item is a file (item.isFile()) or a folder (item.isDirectory()).
  • 4. encoding: 'utf-8' (Used in readFile and writeFile):
    • By default, reading a file returns raw binary data (Buffer).
    • Passing 'utf-8' automatically decodes the Buffer into a human-readable string.
Code Example: Using Attributes in FS
const fs = require('node:fs');

// 1. Recursive Folder Creation (creates parents if missing)
fs.mkdirSync('logs/2026/october', { recursive: true }); 

// 2. Recursive & Forceful Deletion (deletes contents, ignores if not exists)
fs.rmSync('logs', { recursive: true, force: true });

// 3. Reading Directory with File Types
const items = fs.readdirSync('.', { withFileTypes: true });
items.forEach(item => {
    if (item.isDirectory()) console.log(`Folder: ${item.name}`);
});

// 4. Reading file directly into a String (instead of a Buffer)
const text = fs.readFileSync('data.txt', { encoding: 'utf-8' });

  • recursive: mkdir मध्ये गायब असलेले parent folders बनवण्यासाठी आणि rm मध्ये फाईल्सने भरलेले फोल्डर कचऱ्यासकट डिलीट करण्यासाठी.

  • withFileTypes: फोल्डर वाचताना नक्की कोणती फाईल आहे आणि कोणते फोल्डर हे ओळखण्यासाठी.
  • encoding: कॉम्प्युटरची भाषा (Buffer) माणसाला समजणाऱ्या भाषेत (String) वाचण्यासाठी.

Q1. What is the difference between `fs.writeFileSync()` and `fs.appendFileSync()`?
  • fs.writeFileSync() overwrites the entire file. If data was present, it gets deleted and replaced.
  • fs.appendFileSync() adds new data to the very end of the file, preserving all the old data.
Q2. Why is asynchronous file execution preferred in Node.js servers?
  • Node.js runs on a single JavaScript thread. If you use synchronous file operations (like readFileSync), the entire server freezes while reading the file. Asynchronous operations prevent blocking, allowing the server to handle other users' requests simultaneously.
Q3. What is the difference between `fs.unlinkSync()` and `fs.rmdirSync()`?
  • fs.unlinkSync() is strictly used to delete files.
  • fs.rmdirSync() is strictly used to delete empty directories/folders.
Q4. What is "Callback Hell" and how do you solve it in fs module?
  • Callback Hell (also called "Pyramid of Doom") happens when multiple asynchronous callback operations are deeply nested inside each other, making code very hard to read and maintain.
  • This is a common problem with the fs callback API when you need to perform multiple sequential file operations.
  • Solution: Use fs/promises with async/await which flattens the code and makes it linear and readable.
// ❌ CALLBACK HELL (Pyramid of Doom)
fs.readFile('a.txt', 'utf-8', (err, data1) => {
    fs.readFile('b.txt', 'utf-8', (err, data2) => {
        fs.writeFile('output.txt', data1 + data2, (err) => {
            fs.rename('output.txt', 'final.txt', (err) => {
                console.log('Done!'); // deeply nested!
            });
        });
    });
});

// ✅ SOLUTION: async/await (Flat & Clean)
const fsp = require('node:fs/promises');
async function mergeFiles() {
    const data1 = await fsp.readFile('a.txt', 'utf-8');
    const data2 = await fsp.readFile('b.txt', 'utf-8');
    await fsp.writeFile('output.txt', data1 + data2);
    await fsp.rename('output.txt', 'final.txt');
    console.log('Done!'); // linear and clean!
}
mergeFiles().catch(console.error);
Q5. What is the difference between `fs.readFileSync` and `fs.createReadStream`? Which is better for large files?
  • fs.readFileSync() / fs.readFile(): Loads the entire file into memory at once (as a Buffer). If the file is 1 GB, it reserves 1 GB of RAM. This is fine for small files but crashes or slows down for large files.
  • fs.createReadStream(): Reads the file in small chunks (default 64KB). Only one chunk is in memory at a time. This is memory-efficient and ideal for large files (videos, logs, CSVs).
  • Verdict: Always use createReadStream for files larger than a few MB.
// ❌ Bad for large files — loads entire file into RAM
const data = fs.readFileSync('large-video.mp4'); // may crash!

// ✅ Good — reads in 64KB chunks, memory efficient
const stream = fs.createReadStream('large-video.mp4');
stream.on('data', (chunk) => {
    console.log('Chunk received:', chunk.length, 'bytes');
});
stream.on('end', () => {
    console.log('File reading complete!');
});
Q6. What is `ENOENT` error and how do you handle file errors properly?
  • ENOENT stands for "Error NO ENTry" — it means the file or directory you are trying to access does NOT exist.
  • It is the most common error when working with the fs module.
  • Best Practice: Always wrap sync calls in try/catch, and always check the err argument in callbacks.
// Sync: use try/catch
try {
    const data = fs.readFileSync('missing.txt', 'utf-8');
} catch (err) {
    if (err.code === 'ENOENT') {
        console.log('File not found!');
    } else {
        throw err; // rethrow unexpected errors
    }
}

// Async callback: check err argument
fs.readFile('missing.txt', 'utf-8', (err, data) => {
    if (err) {
        if (err.code === 'ENOENT') console.log('File not found!');
        else console.error('Unexpected error:', err);
        return;
    }
    console.log(data);
});

// Promise: use try/catch with async/await
async function safeRead() {
    try {
        const data = await fsp.readFile('missing.txt', 'utf-8');
        console.log(data);
    } catch (err) {
        if (err.code === 'ENOENT') console.log('File not found!');
    }
}
Q7. What are `fs.writeFile` flag options and what does each do?
  • The flag option in writeFile / writeFileSync controls how the file is opened before writing.
  • flag: 'w' (default): Opens file for writing. Creates the file if it doesn't exist. Overwrites existing content.
  • flag: 'a': Opens file for appending. Creates the file if it doesn't exist. Does NOT overwrite.
  • flag: 'wx': Like 'w' but fails if the file already exists. Used to prevent accidental overwrites.
  • flag: 'r': Opens file for reading only. Fails if the file does not exist.
  • flag: 'r+': Opens file for both reading and writing.
// Default: overwrite existing content
fs.writeFileSync('log.txt', 'Entry 1', { flag: 'w' });

// Append to existing content (same as appendFileSync)
fs.writeFileSync('log.txt', '\nEntry 2', { flag: 'a' });

// Fail if file already exists (safe write)
try {
    fs.writeFileSync('config.json', '{}', { flag: 'wx' });
} catch (err) {
    console.log('Config already exists, not overwriting!');
}
Q8. How do you watch a file for changes in Node.js?
  • fs.watch(path, callback): Watches a file or directory for changes. Fires the callback when the file is modified, renamed, or deleted. It is event-driven and very efficient.
  • fs.watchFile(path, callback): Also watches a file, but uses polling (checks the file every interval). Less efficient than fs.watch. Use only when fs.watch is unreliable (e.g., on network file systems).
  • Common use cases: Dev servers (like Nodemon), log monitoring, config hot-reload.
// fs.watch — Event-driven (Efficient)
const watcher = fs.watch('config.json', (eventType, filename) => {
    console.log(`Event: ${eventType}`);     // 'change' or 'rename'
    console.log(`File: ${filename}`);       // 'config.json'
    console.log('File was modified! Reloading...');
});

// Stop watching after 10 seconds
setTimeout(() => watcher.close(), 10000);

// fs.watchFile — Polling-based (Less efficient, but more reliable)
fs.watchFile('config.json', { interval: 1000 }, (curr, prev) => {
    if (curr.mtime !== prev.mtime) {
        console.log('File changed! New size:', curr.size, 'bytes');
    }
});
Q9. Promise-based `fs/promises` vs Callback-based `fs` — Which is better and why?
  • Callback-based `fs`: Old API, still works. Can lead to deeply nested Callback Hell. Error handling requires manual if (err) check in every function.
  • Promise-based `fs/promises`: Modern API (available since Node.js 10+). Works with async/await. Error handling is centralized in a single try/catch block. Code is flat, readable, and maintainable.
  • Verdict: Always prefer fs/promises with async/await in all modern Node.js applications. Use callback-based fs only when working with legacy codebases.
// ❌ Callback (error-prone, nested)
fs.readFile('a.txt', 'utf-8', (err, data) => {
    if (err) return console.error(err);
    fs.writeFile('b.txt', data, (err) => {
        if (err) return console.error(err);
        console.log('Done!');
    });
});

// ✅ Promise (clean, flat, single try/catch)
async function copyFile() {
    try {
        const data = await fsp.readFile('a.txt', 'utf-8');
        await fsp.writeFile('b.txt', data);
        console.log('Done!');
    } catch (err) {
        console.error('Something went wrong:', err.message);
    }
}

Chapter 9.5: The Timers Module

Q. What is the Timers Module in Node.js?

Concept:
  • The timers module in Node.js provides an essential API for scheduling the execution of functions after a specified period of time.
  • It allows developers to handle asynchronous, time-based operations like delays, repeating intervals, and immediate background execution.
  • Unlike many other core modules, the functions in the timers module are globally available. This means you do not need to explicitly use require('timers') to access basic functions like setTimeout or setInterval.
  • Node.js timers are deeply integrated with the Node.js Event Loop and execute in specific phases (like the Timers phase and the Check phase).
  • Timers in Node.js work very similarly to the timers API in web browsers.
  • They are tightly integrated with the Node.js Event Loop.
  • Important Global Timer Methods:
    • setTimeout(): Runs code once after a delay.
    • setInterval(): Runs code repeatedly after a delay.
    • setImmediate(): Runs code immediately after the current I/O event callbacks finish.
मराठी सारांश (Timers Module):
  • timers module वापरून आपण आपला code ठराविक वेळेनंतर रन करू शकतो.
  • हे Node.js मध्ये globally available असते, त्यामुळे याला require() करायची गरज नसते.
  • यामध्ये मुख्यत्वे setTimeout, setInterval आणि setImmediate यांचा वापर होतो.

Q. 1. setTimeout()

Concept:
  • setTimeout is a global timer function used to schedule the execution of a specific callback function after a minimum specified delay.
  • It is designed to execute the provided block of code only once.
  • It returns a Timeout object which can be passed to the clearTimeout() function if you need to cancel the execution before the timer expires.
Syntax & Arguments: setTimeout(callback, delay, [args...])
  • callback: The function containing the code you want to execute after the timer finishes.
  • delay: The time to wait in milliseconds (e.g., 1000 = 1 second) before executing the callback.
  • args...: Optional arguments that will be directly passed into the callback function when it executes.

Q. 2. setInterval()

Concept:
  • setInterval is a global timer function used to repeatedly execute a specific callback function at a regular, continuous time interval.
  • Once started, it will continue to execute indefinitely in the background until it is explicitly stopped by the developer.
  • It returns a Timeout object which must be passed to the clearInterval() function to stop the repeating execution cycle.
Syntax & Arguments: setInterval(callback, delay, [args...])
  • callback: The function containing the code to execute repeatedly.
  • delay: The time interval in milliseconds between each execution of the callback.
  • args...: Optional arguments that will be directly passed into the callback function on every tick.

Q. 3. setImmediate()

Concept:
  • setImmediate is a global timer function designed specifically for Node.js to execute a callback function asynchronously, but as soon as possible.
  • It schedules the callback to run immediately after the current I/O event callbacks finish (specifically in the "Check" phase of the Event Loop).
  • It returns an Immediate object which can be passed to the clearImmediate() function to cancel the pending execution before it fires.
Syntax & Arguments: setImmediate(callback, [args...])
  • callback: The function to execute at the end of the current event loop phase.
  • args...: Optional arguments passed directly into the callback function.
  • Note: It does NOT take a delay argument because it is inherently meant to execute immediately after the current phase finishes.
Code Example: Using and Clearing Timers
// 1. setTimeout (Runs once)
const timeoutId = setTimeout((name) => {
    console.log(`Hello, ${name}! This runs after 2 seconds.`);
}, 2000, 'Vishal');

// To cancel it before it runs:
// clearTimeout(timeoutId);

// 2. setInterval (Runs repeatedly)
let count = 0;
const intervalId = setInterval(() => {
    count++;
    console.log(`Interval tick: ${count}`);
    
    // Stop the interval after 3 ticks
    if (count === 3) {
        clearInterval(intervalId);
        console.log("Interval stopped!");
    }
}, 1000);

// 3. setImmediate (Runs immediately after current I/O phase)
const immediateId = setImmediate(() => {
    console.log("This runs immediately after the current event loop phase!");
});
console.log("This prints FIRST because it is normal synchronous code!");
मराठी सारांश (Syntax & Clearing):
  • setTimeout एखादा कोड एकदाच रन करतो, तर setInterval तो कोड वारंवार रन करतो.
  • दोन्ही methods delay (milliseconds मध्ये) घेतात.
  • कोणताही timer थांबवण्यासाठी आपण तो timer एका variable मध्ये सेव्ह करतो आणि मग clearTimeout किंवा clearInterval ला देतो.
  • setImmediate ला वेळ द्यावा लागत नाही, ते चालू असलेले काम संपल्यावर लगेच रन होते.

Interview Questions (Detailed)

Q1. What is the difference between `setTimeout(..., 0)` and `setImmediate()`?
  • Both schedule a callback to run asynchronously as soon as possible, but they run in different phases of the Event Loop.
  • setTimeout(..., 0) runs in the Timers phase of the event loop.
  • setImmediate() runs in the Check phase of the event loop.
  • If called within an I/O cycle (like reading a file), setImmediate() will always execute before setTimeout(..., 0).
Q2. Is Node.js `setTimeout` guaranteed to run exactly on time?
  • No. Timers in Node.js do not guarantee exact timing. The specified delay is the minimum amount of time before execution.
  • If the Event Loop is blocked by a heavy synchronous operation (like a massive for loop), the timer callback will be delayed until the synchronous operation finishes.

Chapter 10: The Buffer Module

Q. What is a Buffer in Node.js?

Concept:
  • A Buffer is a built-in Node.js class used to handle raw binary data directly in memory.
    • (Raw Binary Data means data that is stored at the lowest machine level as a sequence of bytes (0s and 1s), rather than as human-readable text).
  • It represents data as a sequence of bytes and is commonly used with file systems, network streams, images, and encryption.
  • JavaScript originally only handled strings, objects, arrays, and numbers. It didn't have a way to handle binary data (like images, videos, TCP packets). Buffer solves this in Node.js.
  • A Buffer is a sequence of 8-bit unsigned values (from 0 to 255).
  • Buffer is globally available in Node.js, so you don't necessarily need to import it, though modern practice recommends const { Buffer } = require('node:buffer');.
मराठी सारांश:
  • Buffer म्हणजे बायनरी डेटा (0 आणि 1) मेमरीमध्ये साठवण्यासाठी वापरलेली जागा.
  • जेव्हा आपण फोटो, व्हिडिओ किंवा नेटवर्क डेटावर काम करतो, तेव्हा Node.js त्याला Buffer मध्ये साठवतो.

Q. Key Characteristics of a Buffer

  • Fixed-Size (Size is Immutable): Once a Buffer is created, its size (length) CANNOT be changed. If you need more space, you must create a new, larger Buffer.
  • Mutable Content: Even though the size is fixed, the data inside the Buffer can be changed/modified at any time (e.g., buf[0] = 88;).
  • External Memory: Buffers allocate memory outside of the V8 JavaScript engine's normal heap garbage collection mechanism. It interacts directly with system RAM for efficiency.
  • Uint8Array: Under the hood, Buffer is built on top of JavaScript's Uint8Array.
मराठी सारांश:
  • Buffer चा आकार एकदा ठरवला की तो बदलता येत नाही (Fixed size).
  • पण आतला डेटा आपण बदलू शकतो (Mutable).
  • Buffer ची मेमरी V8 इंजिनच्या बाहेर, थेट सिस्टिमच्या RAM मध्ये साठवली जाते.

Q. Methods to Create a Buffer

Concept:
  • Buffers must be created by allocating memory or converting existing data (like strings or arrays) into binary format.
  • We cannot use the new Buffer() constructor anymore (it is deprecated for security reasons). We use static methods like .from(), .alloc(), or .allocUnsafe().
1. Syntax: Buffer.from(data, [encoding])
  • data: The string, array, or another buffer to convert into a Buffer.
  • encoding: (Optional) The character encoding of the string (e.g., 'utf-8').
  • Usage: Used to directly convert an existing string into binary data.

2. Syntax: Buffer.alloc(size)
  • size: The number of bytes to allocate (Integer).
  • Usage: Creates a clean, safe Buffer of the specified size where all bytes are initialized to 0. (Safe but slightly slower).

3. Syntax: Buffer.allocUnsafe(size)
  • size: The number of bytes to allocate (Integer).
  • Usage: Creates a Buffer without initializing the memory. It is extremely fast but may contain old, sensitive garbage data. It MUST be fully overwritten before reading.
मराठी सारांश (Buffer Creation):
  • Buffer.alloc(size) वापरून आपण सुरक्षित (0 ने भरलेला) Buffer बनवतो.
  • Buffer.allocUnsafe(size) हा फास्ट असतो पण त्यात जुना कचरा डेटा (garbage values) असू शकतो, त्यामुळे तो काळजीपूर्वक वापरावा.

Q. Encoding and Conversion

Concept:
  • Since Buffers are just 0s and 1s, we frequently need to convert them back to human-readable strings or specific formats like Base64 or Hex.
Syntax: buf.toString([encoding])
  • encoding: The format to convert the binary data into.
    • 'utf-8' (Default): Standard text conversion.
    • 'hex': Converts bytes into a hexadecimal string.
    • 'base64': Converts the Buffer into a Base64 string (widely used for transmitting images/files over text protocols like HTTP). Base64 does NOT compress data, it just changes format.
  • Length Trap: "😀".length in JS is 2 (characters), but Buffer.from("😀").length is 4 (because UTF-8 uses 4 bytes to represent this emoji).

Q. Other Important Buffer Operations

1. Syntax: buf.write(string)
  • string: The text you want to inject/overwrite into an existing buffer.
  • Usage: Modifies the content of an existing buffer in-place.

2. Syntax: Buffer.compare(buf1, buf2)
  • buf1, buf2: The two buffers to compare byte-by-byte.
  • Returns: -1 if buf1 is less, 1 if buf1 is greater, and 0 if they are exactly identical.

3. Syntax: Buffer.concat(list)
  • list: An array of multiple Buffer objects.
  • Returns: A single, new combined Buffer.
Code Example: Basic Buffer Operations
// 1. Create a buffer from string
const buf1 = Buffer.from("NodeJS");
console.log(buf1); // <Buffer 4e 6f 64 65 4a 53>
console.log(buf1.toString()); // "NodeJS"

// 2. Modify Buffer Content
buf1[0] = 77; // ASCII for 'M'
console.log(buf1.toString()); // "ModeJS" (Mutable content!)

// 3. Convert to Base64
console.log(buf1.toString("base64")); // "TW9kZUpT"

// 4. Concatenate Buffers
const bufA = Buffer.from("Hello ");
const bufB = Buffer.from("World");
const combined = Buffer.concat([bufA, bufB]);
console.log(combined.toString()); // "Hello World"

// 5. Writing to a Buffer
const bufAlloc = Buffer.alloc(10);
bufAlloc.write("vishal");
console.log(bufAlloc.toString()); // "vishal"

// 6. Comparing Buffers
const b1 = Buffer.from("ABC");
const b2 = Buffer.from("BCD");
console.log(Buffer.compare(b1, b2)); // -1 (b1 is less than b2)
मराठी सारांश:
  • Buffer मधील डेटा माणसाला वाचता यावा यासाठी toString() चा वापर होतो.
  • आपण त्यात नवीन डेटा लिहिण्यासाठी .write() वापरू शकतो आणि दोन Buffer ची तुलना करण्यासाठी Buffer.compare() वापरता येतो.

Interview Questions (Detailed)

Q1. What is the difference between `Buffer.alloc()` and `Buffer.allocUnsafe()`?
  • Buffer.alloc(size) creates a zero-filled, initialized Buffer. It is slower but very safe.
  • Buffer.allocUnsafe(size) creates an uninitialized Buffer. It is faster but might contain old, sensitive memory data. It should always be completely overwritten before reading.
Q2. Are Buffers mutable or immutable?
  • The size of a Buffer is immutable (fixed).
  • The content inside a Buffer is mutable (can be changed).
Q3. Is a Buffer an Array?
  • No. A Buffer behaves like an array of bytes and uses indexing (buf[0]), but it is actually a subclass of Uint8Array. It lives in external memory, not the standard JS array heap.
Q4. What is the relationship between Buffers and Streams? (Missing Important Concept)
  • This is a critical concept: Streams process data in chunks, and those chunks are Buffers.
  • When you read a large file using fs.createReadStream(), or receive a large video over HTTP, Node.js doesn't load the entire file into RAM.
  • Instead, it breaks the data into smaller pieces (chunks). By default, these chunks are returned as Buffer objects.
  • Buffers are the fundamental data structures that make Node.js Streams work efficiently.
मराठी सारांश:
  • Interview मध्ये alloc() vs allocUnsafe() हमखास विचारतात. allocUnsafe() फास्ट असतो पण सुरक्षित नसतो.
  • "Buffer Mutable असतो का?" यावर सांगा की त्याचा आकार फिक्स (immutable) असतो, पण आतला डेटा बदलता (mutable) येतो.
  • Buffers आणि Streams: Streams जो डेटा तुकड्या-तुकड्यात (chunks) आणतात, ते तुकडे म्हणजेच Buffers असतात.

Concept:
  • The searchParams property returns a URLSearchParams object which acts like a Map for query parameters.
  • It makes reading, adding, or deleting ?key=value pairs extremely easy without manual string manipulation.

    urlObj.searchParams.has('status') // true

    urlObj.searchParams.set('status', 'inactive')
  • 5. append(name, val): Adds a new parameter. If it exists, it creates a duplicate.
    urlObj.searchParams.append('limit', '10')
  • 6. delete(name): Completely removes a parameter from the URL.
    urlObj.searchParams.delete('status')

Chapter 11: The Events Module

Q. What is the Events Module in Node.js?

Concept:
  • The events module is a built-in Node.js module that facilitates the event-driven architecture.
  • It provides the EventEmitter class, which allows you to create, fire (emit), and listen to custom events.
  • Node.js is heavily event-driven. Many of Node's built-in modules (like fs, http, stream) are built directly on top of the EventEmitter architecture.
  • To use it, you import the class and create an instance: const { EventEmitter } = require('node:events');
मराठी सारांश:
  • Node.js मधील सगळी कामे इव्हेंट्स (Events) च्या आधारावर चालतात.
  • events module आपल्याला स्वतःचे इव्हेंट्स बनवायला (emit) आणि त्यांना ऐकायला (listen) मदत करते.

Q. What is an EventEmitter, Uses & Advantages?

  • What is it? An EventEmitter is simply an object that sends out a signal (event) when something happens. Other parts of your code can "listen" for that signal and execute a callback function in response.
  • Uses:
    • Handling HTTP requests (Server emits a 'request' event).
    • Reading/Writing files (Streams emit 'data' and 'end' events).
    • Building real-time chat applications or notification systems.
  • Advantages:
    • Decoupling: The sender (emitter) doesn't need to know anything about the receiver (listener). This makes the code highly modular.
    • Asynchronous Flow: Perfect for non-blocking I/O tasks. You don't wait for a task to finish; you just listen for an event to fire when it finishes.
    • Multiple Listeners: A single event can trigger multiple independent actions across different parts of the application.

Q. Key Concepts: Listeners and Emitters

  • 1. Listening (.on): You can attach event handlers using the .on('eventName', callback) method. The callback executes whenever that specific event is fired.
  • 2. Emitting (.emit): You use .emit('eventName') to trigger the event. You can also pass data (arguments) to the event handlers.
  • 3. Multiple Callbacks: You can register multiple .on() listeners for the same single event. When emitted, all of them will run in the order they were registered.
मराठी सारांश:
  • .on() चा वापर करून आपण इव्हेंट ऐकतो (Listen) आणि .emit() चा वापर करून आपण इव्हेंट फायर (Trigger) करतो.
  • आपण एकाच इव्हेंटसाठी अनेक कामे सेट करू शकतो.
Figure 18: How EventEmitter works

Q. Essential EventEmitter Methods

1. Syntax: emitter.on(eventName, listener)
  • eventName: The name of the event (string).
  • listener: The callback function to execute.
  • Usage: Adds a listener. The callback runs every time the event is emitted.

2. Syntax: emitter.emit(eventName, [...args])
  • eventName: The name of the event to fire.
  • ...args: (Optional) Data to pass to the listener functions.
  • Usage: Synchronously calls all registered listeners for the event.

3. Syntax: emitter.once(eventName, listener)
  • Usage: Adds a one-time listener. It is called only the first time the event is emitted, and then automatically unregisters itself.

4. Syntax: emitter.off(eventName, listener) or removeListener
  • Usage: Removes a specific listener from the event array.

5. Syntax: emitter.removeAllListeners([eventName])
  • Usage: Removes all listeners for a specific event, or all listeners for all events if no name is provided.
Code Example: Basic Emitter Methods
const { EventEmitter } = require('events');
const myEmitter = new EventEmitter();

// 1. Registering multiple listeners (.on)
myEmitter.on('userJoined', (username, id) => {
    console.log(`Welcome ${username}! Your ID is ${id}`);
});
myEmitter.on('userJoined', () => {
    console.log(`Updating database for new user...`);
});

// 2. Registering a one-time listener (.once)
myEmitter.once('firstLogin', () => {
    console.log('Sending welcome email (Will only happen once!)...');
});

// 3. Emitting the events (.emit)
myEmitter.emit('firstLogin'); // Output: Sending welcome email...
myEmitter.emit('firstLogin'); // Ignored! (.once already ran)

myEmitter.emit('userJoined', 'Vishal', 101); // Output: Welcome Vishal! + Updating database...

Q. PRO TIP 1: The special 'error' Event (Crash Risk!)

  • In Node.js, the 'error' event is treated specially.
  • If an EventEmitter emits an 'error' event, and no listener is registered to handle it, the Node.js process will print the stack trace and CRASH (exit).
  • Best Practice: ALWAYS register an .on('error', (err) => {...}) listener on your emitters to prevent your server from crashing.
मराठी सारांश (Important Error Handling):
  • Node.js मध्ये 'error' नावाचा इव्हेंट खूप खास (Special) असतो.
  • जर आपण 'error' नावाचा इव्हेंट फायर (emit) केला, आणि त्याला पकडण्यासाठी (listen) कोणीच नसेल (म्हणजेच .on('error', ...) लिहिलं नसेल), तर Node.js ला वाटतं की काहीतरी गंभीर चूक झाली आहे.
  • यामुळे पूर्ण Node.js सर्वर क्रॅश होतो आणि प्रोग्राम तिथेच थांबतो (Crash & Exit).
  • Best Practice: सर्व्हर क्रॅश होण्यापासून वाचवण्यासाठी नेहमी प्रत्येक Emitter वर .on('error', (err) => {...}) लिहून एरर हँडल करावी.

Q. PRO TIP 2: Extending EventEmitter (Real-World Use)

  • In large applications, we rarely create empty new EventEmitter() instances.
  • Instead, custom classes extend the EventEmitter class. This gives the custom class the ability to emit its own internal events.
  • This is exactly how Node.js core modules work (e.g., the http.Server class extends EventEmitter, which is why we can do server.on('request', ...)).
Code Example: Extending EventEmitter
const { EventEmitter } = require('events');

// Our custom class gets all features of EventEmitter!
class MyServer extends EventEmitter {
    start() {
        console.log("Server is starting...");
        // Emitting an event from inside the class
        this.emit('started', { port: 8080 });
    }
}

const server = new MyServer();

// Listening to the custom event
server.on('started', (data) => {
    console.log(`Successfully running on port ${data.port}`);
});

server.start();

Interview Questions (Detailed)

Q1. What happens if you trigger `.emit()` before setting `.on()`?
  • Nothing happens. The event is fired, but because there are no listeners registered yet, the event is completely ignored. Listeners must be set before the event is emitted.
Q2. What is the difference between `.on()` and `.once()`?
  • .on() will execute its callback every time the event is fired, no matter how many times.
  • .once() will execute its callback only the first time the event is fired, and then it automatically unregisters itself.
Q3. What happens if an EventEmitter throws an 'error' event without a listener?
  • It throws an unhandled exception and crashes the entire Node.js process. Always attach an .on('error') listener to prevent crashes.
Q4. What happens if multiple listeners are attached to the same event? Is there a limit?
  • When the event is emitted, all attached listeners will execute synchronously in the exact order they were registered.
  • Limit Warning: By default, Node.js allows a maximum of 10 listeners per event to prevent memory leaks.
  • If you add more than 10, Node.js will print a MaxListenersExceededWarning in the console.
  • Fix: You can increase this limit using emitter.setMaxListeners(n).

  • Q. .on() च्या आधी .emit() कॉल केला तर काय होईल?

  • Q. .on() आणि .once() मधला फरक काय?
    उत्तर: .on() वापरला तर इव्हेंट जितक्या वेळा फायर होईल, तितक्या वेळा कोड चालेल. पण .once() वापरला तर कोड फक्त पहिल्यांदाच चालेल आणि नंतर तो आपोआप बंद (unregister) होईल.

Chapter 12: The Stream Module

Q. What is a Stream in Node.js?

Concept:
  • A Stream is an abstract interface and a fundamental concept in Node.js that lets you read data from a source or write data to a destination in a continuous, chunk-by-chunk fashion.
  • Ongoing Process: Think of a stream as an ongoing process where we have to read (or write) data chunk by chunk as it comes in, rather than waiting for the entire dataset to load into memory.
  • This means you process data piece by piece as soon as it becomes available.
  • Important: All streams in Node.js are instances of the EventEmitter class. This means they broadcast events (like 'data', 'end', and 'error') which we can listen to.
  • Analogy: Streaming is exactly like watching a video on YouTube. You watch it in real-time as small parts (buffer chunks) arrive, instead of waiting to download the entire 2GB video file before you can press play.
  • Why is it used? Streams are heavily used in Node.js for reading/writing huge files, handling HTTP requests/responses, and processing network sockets without crashing the server due to RAM limits.
मराठी सारांश (Detailed):
  • Stream म्हणजे काय? Stream म्हणजे असा मार्ग ज्यातून डेटा पूर्णपणे एकाच वेळी न येता, छोट्या-छोट्या तुकड्यांमध्ये (Chunks) सतत वाहत असतो.
  • फायदा (Advantage): जर तुम्हाला 2GB ची फाईल वाचायची असेल, तर Node.js ती पूर्ण फाईल मेमरी (RAM) मध्ये लोड करत नाही. त्याऐवजी, तो थोडा-थोडा डेटा वाचतो आणि प्रोसेस करतो. यामुळे कितीही मोठी फाईल असली तरी मेमरी (RAM) वाचते आणि सर्वर क्रॅश होत नाही (Highly Memory Efficient).
  • उदाहरण (Example): यूट्यूब (YouTube) किंवा नेटफ्लिक्स (Netflix). आपण तिथे पूर्ण चित्रपट आधी डाउनलोड करत नाही, तर थोडा-थोडा डेटा येत राहतो आणि आपण तो बघत राहतो. हेच काम Node.js मध्ये Streams करतात.
  • सर्वात महत्वाची गोष्ट म्हणजे सर्व Streams हे EventEmitter असतात, म्हणजेच ते 'data' आणि 'end' सारखे इव्हेंट्स फायर करतात.

Q. 4 Types of Streams (In Detail)

  • 1. Readable Stream: A stream from which you can read data sequentially. It acts as a source.
    • Examples: fs.createReadStream() (Reading a file), process.stdin (Reading user input from terminal), req in HTTP (Reading incoming request body).
  • 2. Writable Stream: A stream to which you can write data sequentially. It acts as a destination.
    • Examples: fs.createWriteStream() (Writing to a file), process.stdout (Printing to the console), res in HTTP (Sending a response back to the client).
  • 3. Duplex Stream: A stream that is BOTH Readable and Writable. The read and write channels operate independently (like a two-way road).
    • Example: A TCP network socket (net.Socket). You can read data coming from a client and write data back to the client simultaneously.
  • 4. Transform Stream: A very special type of Duplex stream. Here, the data you WRITE is mathematically modified or transformed before it is READ.
    • Examples: zlib.createGzip() (Data goes in as text, gets compressed, and comes out as a zip binary), Encryption streams (Data goes in raw, comes out encrypted).

मराठी सारांश:
  • Streams चे ४ प्रकार असतात: वाचण्यासाठी Readable, लिहिण्यासाठी Writable, दोन्ही करण्यासाठी Duplex, आणि डेटा बदलून पुढे पाठवण्यासाठी Transform.

Q. Common Stream Events (Detailed Explanation)

  • 'data' (Readable): This event is fired continuously whenever a new chunk of data becomes available to read. When you listen to this event, the stream automatically starts flowing.
  • 'end' (Readable): This event is fired when the stream has reached the end of the file/source and there is no more data left to read. Useful for closing connections or sending a final response.
  • 'error' (Readable/Writable): Fired immediately if there is any error during the reading or writing process (e.g., file not found, permission denied). If you don't handle this, your server will crash!
  • 'finish' (Writable): This event is fired on a Writable stream when you have called .end() and all chunks have been successfully flushed/written to the destination.
Code Example: Handling Streams Manually with Events
const fs = require('fs');
const http = require('http');

const server = http.createServer((req, res) => {
    // 1. Create a readable stream
    const readStream = fs.createReadStream("large-data.txt", "utf-8");
    
    // 2. Listen to the 'data' event
    readStream.on("data", (chunk) => {
        res.write(chunk); // Send chunk to the client/browser
    });

    // 3. Listen to the 'end' event
    readStream.on("end", () => {
        res.end(); // Close the response when file ends
    });

    // 4. Handle errors!
    readStream.on("error", (err) => {
        console.error(err);
        res.statusCode = 500;
        res.end("File not found");
    });
});

Q. The stream.pipe() Method (The Easy Way)

Concept:
  • stream.pipe() is a utility method that connects a Readable stream directly to a Writable stream.
  • It automatically handles the reading, writing, and flow control (backpressure) so you don't have to manually write .on('data') and .on('end') events.
  • Benefits: Memory efficiency, heavily simplified code, and you can "chain" multiple pipes (e.g., Read → Compress → Write).
Syntax: readableStream.pipe(destinationStream, [options])
  • readableStream: The source stream you are reading from (e.g., fs.createReadStream).
  • destinationStream: The writable stream you are sending data to (e.g., HTTP res, or fs.createWriteStream).
  • Returns: The destination stream, which allows for chaining like a.pipe(b).pipe(c).
Code Example: Using .pipe()
const fs = require('fs');
const http = require('http');

const server = http.createServer((req, res) => {
    const readStream = fs.createReadStream("large-data.txt", "utf-8");
    
    // Connect the read stream directly to the HTTP response (which is a Writable stream!)
    // This ONE line replaces all the .on('data') and .on('end') logic!
    readStream.pipe(res);
    
    readStream.on("error", (err) => {
        res.statusCode = 500;
        res.end("Error occurred");
    });
});
मराठी सारांश:
  • .pipe() चा वापर करून आपण एका Readable stream मधून डेटा थेट Writable stream मध्ये पाठवू शकतो.
  • यामुळे कोड खूप सोपा होतो (फक्त एका लाईनमध्ये काम होते) आणि मेमरी मॅनेजमेंट (Backpressure) Node.js स्वतः हाताळते.

Interview Questions (Detailed)

Q1. Why are Streams preferred over `fs.readFile` for large files?
  • fs.readFile() loads the entire file into RAM before sending it. If the file is 2GB and the server only has 1GB of RAM, the application will crash.
  • A Stream reads and sends the file in tiny chunks (e.g., 64KB at a time), keeping RAM usage extremely low regardless of the file size.
Q2. Can we pipe a Writable stream into a Readable stream?
  • No. Data always flows FROM a Readable stream TO a Writable stream. readStream.pipe(writeStream) is correct. writeStream.pipe(...) will throw an error.
Q3. What is a Duplex stream vs a Transform stream?
  • Both can read and write. But in a Duplex stream (like a TCP socket), the read and write channels are independent. In a Transform stream (like zlib compression), the output data is mathematically computed from the input data.

Q. What is the Crypto module in Node.js?

Concept:

Q. Important Cryptographic Concepts

Figure: Summary of Core Cryptographic Concepts
  • 1. Hashing (e.g., SHA-256):
    • Definition: Hashing is a mathematical one-way function that maps data of any arbitrary size to a fixed-size string of characters, typically representing a digital fingerprint of the data.
    • You cannot reverse a hash back to the original data (it is strictly a one-way process).
    • Mainly used for storing passwords securely so that even if the database is hacked, actual passwords remain hidden.
    Example: 
    const hash = crypto.createHash('sha256').update('password123').digest('hex');
  • 2. Encryption & Decryption (e.g., AES-256):
    • Definition: Encryption is a two-way cryptographic process that scrambles readable data (plaintext) into an unreadable format (ciphertext) using an algorithm and a secret key.
    • The data can be decrypted back to its original form only if you have the exact corresponding secret key.
    • Used for protecting sensitive user data (like credit card details or chat messages) while transmitting or storing.
    Example: 
    // Encryption requires a Cipher, Decryption requires a Decipher with the same key
const cipher = crypto.createCipheriv('aes-256-cbc', key, iv);
  • 3. HMAC (Hash-based Message Authentication Code):
    • Definition: HMAC is a specific type of message authentication code (MAC) involving a cryptographic hash function (like SHA-256) combined with a secret cryptographic key.
    • Used to verify both data integrity (ensuring data hasn't changed) and authenticity (ensuring it came from the right sender).
    • Widely used in JWT (JSON Web Tokens) and securing API webhooks.
    Example: 
    const hmac = crypto.createHmac('sha256', 'my_secret_key').update('Message').digest('hex');
  • 4. Salting:
    • Definition: A salt is unique, randomly generated data that is added as an additional input to a one-way hash function before hashing a password.
    • It guarantees a unique hash even if two different users happen to have the exact same password.
    • Protects against common security vulnerabilities like dictionary attacks and rainbow table attacks.
    Example: 
    const salt = crypto.randomBytes(16).toString('hex');
const hashedPassword = crypto.scryptSync('password123', salt, 64).toString('hex');

Q. Types of Cryptographic Algorithms & Which is Better?

  • 1. General Hashing Algorithms (For Data & Files):
    • MD5 & SHA-1: Extremely fast but OUTDATED and INSECURE. Easily broken by modern computers (collision attacks). Do not use them.
    • SHA-256 / SHA-512: Secure, standard algorithms used for hashing data (like verifying file integrity, digital signatures).
    • Verdict: Use SHA-256 or SHA-512 for general data hashing. 
      const hash = crypto.createHash('sha256').update('DocumentData').digest('hex');
  • 2. Password Hashing Algorithms (Key Derivation):
    • Standard hashing (like SHA-256) is too fast. Hackers can compute billions of SHA-256 hashes per second (brute-force). Password algorithms are intentionally made slow and memory-heavy to prevent this.
    • PBKDF2: Older standard. Decent, but mostly replaced by newer algorithms.
    • bcrypt: Very popular, highly secure, slow by design. Requires a third-party npm package (npm i bcrypt).
    • scrypt: Highly secure, memory-hard (stops hackers from using GPUs to crack passwords). Best part: It is built-in to the Node.js crypto module!
    • Argon2: The most secure and modern algorithm (won the Password Hashing Competition). Requires a third-party package.
    • Verdict: Use scrypt if you want zero external dependencies (built-in). Use bcrypt or Argon2 for modern industry-standard security. 
      // Example using bcrypt (npm i bcrypt)
const bcrypt = require('bcrypt');
const hashedPwd = await bcrypt.hash('mypassword123', 10); // 10 is the salt rounds
  • 3. Encryption Algorithms:
    • Definition of Symmetric Encryption: A method where the same single secret key is used to both lock (encrypt) and unlock (decrypt) the data. It is like a house key that both locks and unlocks the door.
      Best Algorithm: AES-256 (Advanced Encryption Standard). It is extremely fast and used for encrypting database fields, files, and chat messages.
    • Definition of Asymmetric Encryption: A method that uses a pair of different keys: a Public Key (shared with everyone to lock data) and a Private Key (kept strictly secret to unlock it). It is like a mailbox where anyone can drop a letter (public key), but only you have the key to open it (private key).
      Best Algorithm: RSA. It is slower than symmetric encryption but highly secure, mainly used for SSL/TLS (HTTPS) certificates and SSH keys.
    • Verdict: Use AES-256-CBC or AES-256-GCM for standard encryption of your application data. 
      // AES-256 Encryption Example
const cipher = crypto.createCipheriv('aes-256-cbc', Buffer.from(key), iv);
let encrypted = cipher.update('Sensitive Data', 'utf8', 'hex');
encrypted += cipher.final('hex');
मराठी सारांश (अल्गोरिदमची निवड):
  • 1. Data Hashing (डेटासाठी):
    • नेहमी SHA-256 किंवा SHA-512 वापरा (उदा. फाईलचे checksums किंवा डिजिटल सिग्नेचरसाठी).
    • MD5 किंवा SHA-1 कधीही वापरू नका कारण ते आता जुने आणि असुरक्षित (hackable) आहेत.
  • 2. Password Hashing (पासवर्डसाठी):
    • Passwords साठी SHA-256 चालत नाही कारण ते खूप फास्ट आहे, ज्यामुळे हॅकर्स एका सेकंदात करोडो passwords तपासून पाहू शकतात.
    • Passwords सुरक्षित ठेवण्यासाठी नेहमी bcrypt, Argon2 (थर्ड पार्टी पॅकेजेस) किंवा Node.js मधील इन-बिल्ट scrypt वापरा.
    • हे अल्गोरिदम्स मुद्दाम slow आणि memory-heavy डिझाईन केलेले असतात ज्यामुळे हॅकिंग करणे अत्यंत कठीण जाते.
  • 3. Encryption (डेटा लपवण्यासाठी):
    • Symmetric (एकाच चावीने लॉक/अनलॉक): AES-256 हा सर्वोत्तम, सर्वात फास्ट आणि जास्त वापरला जाणारा अल्गोरिदम आहे (उदा. database मधील माहिती किंवा चॅट्स लपवण्यासाठी).
    • Asymmetric (पब्लिक आणि प्रायव्हेट चावी): RSA वापरला जातो. हा slow असतो पण HTTPS/SSL certificates आणि सुरक्षित कनेक्शनसाठी (Secure Key Exchange) वापरला जातो.

Q. Hashing Passwords with scrypt

  • scrypt is a password-based key derivation function designed to be computationally intensive, making brute-force attacks much harder.
  • It is the recommended built-in method for hashing passwords in Node.js.

  if (err) throw err;
  console.log('Salt:', salt);
  console.log('Hashed Password:', derivedKey.toString('hex'));
});

Q. Full Usage Example: HMAC (Signing & Verifying)

  • This shows how a message (like a Webhook payload or a JWT) is signed, and then verified to ensure it wasn't tampered with.
  • Syntax & Arguments:
    • crypto.createHmac(algorithm, key)
    • algorithm: The hashing algorithm to use (e.g., 'sha256').
    • key: The secret cryptographic key used to sign the data. Only those with the key can verify or create the signature.
    • .update(data): The actual message or payload to sign.
    • .digest(encoding): Outputs the final HMAC signature in the specified encoding (like 'hex').
  • Code Example: 
    const crypto = require('node:crypto');

const secretKey = 'my_super_secret_key';
const message = JSON.stringify({ userId: 101, amount: 500 });

// 1. Sender: Creates an HMAC signature for the message
const signature = crypto.createHmac('sha256', secretKey).update(message).digest('hex');
console.log('Signature:', signature);

// 2. Receiver: Verifies the received message with their own generated signature
const receivedMessage = message; 
const receivedSignature = signature;

const verifySignature = crypto.createHmac('sha256', secretKey).update(receivedMessage).digest('hex');
if (verifySignature === receivedSignature) {
    console.log('Success: Data is authentic and has not been changed!');
} else {
    console.log('Error: Data was tampered with!');
}

Q. Full Usage Example: Symmetric Encryption (AES-256)

  • This shows how you encrypt and then later decrypt sensitive data (like a chat message or bank account number).
  • Syntax & Arguments (Encryption/Decryption):
    • crypto.createCipheriv(algorithm, key, iv) / crypto.createDecipheriv(algorithm, key, iv)
    • algorithm: The encryption algorithm to use (e.g., 'aes-256-cbc').
    • key: The secret key used to lock/unlock. For AES-256, it MUST be exactly 32 bytes long.
    • iv: Initialization Vector. A random string (16 bytes for CBC) used to ensure that encrypting the same text twice yields different ciphertexts. Must be passed along with the encrypted data to decrypt it.
    • .update(data, inputEncoding, outputEncoding): Processes the data.
    • .final(outputEncoding): Returns any remaining encrypted/decrypted data.
  • Code Example: 
    const crypto = require('node:crypto');

// Setup: Key and IV (Initialization Vector)
const algorithm = 'aes-256-cbc';
const key = crypto.randomBytes(32); // 32 bytes required for AES-256
const iv = crypto.randomBytes(16);  // 16 bytes required for CBC mode

const sensitiveData = "This is a highly confidential message!";

// 1. ENCRYPT (Lock)
const cipher = crypto.createCipheriv(algorithm, key, iv);
let encrypted = cipher.update(sensitiveData, 'utf8', 'hex');
encrypted += cipher.final('hex');
console.log('Encrypted Data:', encrypted);

// 2. DECRYPT (Unlock)
const decipher = crypto.createDecipheriv(algorithm, key, iv);
let decrypted = decipher.update(encrypted, 'hex', 'utf8');
decrypted += decipher.final('utf8');
console.log('Decrypted Data:', decrypted); // Should match original!

Q. What is a Web Server?

Definition: A web server is an application that listens for incoming HTTP requests from clients (like browsers) and sends back appropriate responses (HTML pages, JSON data, images, etc.).
  • Node.js provides a built-in http module to create a highly efficient, event-driven, non-blocking web server.
  • http.createServer((req, res) => {}) takes a callback that fires every time a new request hits the server.
  • req (Request): Contains info about the incoming request (e.g., req.url, req.method, headers).
  • res (Response): Used to send data back to the client (e.g., res.write(), res.end()).
Code Example: Creating a Basic Web Server
const http = require("node:http");

const server = http.createServer((req, res) => {
    res.end("Hello, Welcome to Node.js server!");
});

// Start the server on port 4000
server.listen(4000, "127.0.0.1", () => {
    console.log("Server started on port 4000");
});
मराठी सारांश:
  • Web Server म्हणजे असा program जो ब्राउझर कडून आलेल्या HTTP request ला हाताळतो आणि योग्य ते response (उत्तर) पाठवतो.
  • Node.js मध्ये आपण http module चा वापर करून आपला स्वतःचा server बनवू शकतो.

Q. What is Routing?

  • Routing means responding to different URL endpoints (e.g., /home, /about) with different content.
  • In a native Node.js HTTP server, we handle routing manually using if/else statements based on req.url and req.method.
  • Status Codes & Headers: We use res.writeHead(status, headers) to send HTTP status codes (e.g., 200 OK, 404 Not Found) and specify the Content-Type (like text/html or application/json).
Code Example: Manual Routing
const http = require("node:http");

const server = http.createServer((req, res) => {
    if (req.url === "/" || req.url === "/home") {
        res.end("<h1>Welcome To Home Page!</h1>");
        
    } else if (req.url === "/about") {
        res.end("<h1>About Us Page</h1>");
        
    } else {
        // Handle 404 Route Not Found
        res.writeHead(404, { "Content-Type": "text/html" });
        res.end("<h1>404: Page Not Found!</h1>");
    }
});

server.listen(4000, () => console.log("Running..."));
मराठी सारांश:
  • Routing म्हणजे युजरने मागितलेल्या URL नुसार (उदा.
  • /about) त्याला वेगळी माहिती दाखवणे.
  • यासाठी आपण req.url चा वापर करतो.
  • जर पेज नसेल तर आपण 404 Status Code पाठवतो.

Q. Creating a Simple JSON API

  • An API (Application Programming Interface) route returns raw data (usually JSON) instead of HTML.
  • To build an API, we set the header Content-Type: application/json and send a stringified JSON object.
  • Pro Tip: If your API returns data from a large .json file, read it synchronously once at the top of the file using fs.readFileSync(). Do not read it inside createServer, or it will unnecessarily read the file from the hard drive for every single user request!
Code Example: A Simple User API
const http = require("node:http");
const fs = require("node:fs");

// READ FILE ONLY ONCE when server starts
const apiData = fs.readFileSync("userApi.json", "utf-8");

const server = http.createServer((req, res) => {
    if (req.url === "/api/users") {
        res.writeHead(200, { "Content-Type": "application/json" });
        // Send the pre-loaded JSON data directly!
        res.end(apiData);
    } else {
        res.writeHead(404);
        res.end("API route not found");
    }
});

  • Request आल्यावर वारंवार वाचू नये, यामुळे सर्वर slow होतो.

Interview Questions (Detailed)

Q1. What is the difference between res.write() and res.end()?
  • res.write() can be called multiple times to send chunks of the response body. It keeps the connection open.
  • res.end() signals that all headers and body have been sent. The server considers the response complete and closes the connection. You MUST call res.end(), or the browser will keep spinning infinitely.
Q2. Why do we need res.writeHead()?
  • It sends HTTP response headers to the client. We need it to tell the browser the Status Code (e.g., 200 for Success, 404 for Not Found) and the Content-Type (e.g., text/html or application/json), so the browser knows how to parse the data.
Q3. Why is it bad practice to read a JSON file asynchronously inside the server callback?
  • If you use fs.readFile() inside createServer, the server will read the file from the hard drive on every single request. For 1000 users, it reads the disk 1000 times, which is extremely slow and resource-heavy. Reading it synchronously once outside the server caches it in memory.
Q4. What is the difference between setHeader() and writeHead()?
  • setHeader(): Useful for adding or overriding individual headers incrementally before sending the response.
  • writeHead(): Ideal for setting the status code and multiple headers at once. It forces the headers to be sent immediately.
Q5. What is the res.write() method?
  • The res.write() method is used to send a chunk of the response body to the client. It can be called multiple times to stream data to the client before ending the response with res.end().
Q6. What is a Stream in Node.js?
  • A stream is an ongoing process of reading or writing data chunk by chunk, without waiting for the entire file to be loaded in memory. We use Buffers to hold multiple chunks and work with them.

Q5. Is it possible to use all HTTP requests (GET, POST, PUT, PATCH) with middleware?
  • Yes, it is possible. You can chain middleware or apply it to specific HTTP verbs and routes.
Q6. How do we handle modular routing in Express?

  • 2. Resource-Based: Data is treated as "Resources" (like users, posts, photos). Each resource is accessed via a unique URI (e.g., https://api.example.com/users).

  • PUT: To update an existing resource (Full replacement).
  • PATCH: To update an existing resource (Partial update).
  • DELETE: To remove a resource.

SECTION 6: NODE.JS INTERNAL ARCHITECTURE

Chapter 19: How JS Works (V8 Engine & Event Loop)

Q. How does JavaScript execute our code?

  • When you run a JavaScript file, the JavaScript Engine (like V8 in Chrome/Node.js) takes over.
  • It performs 3 main steps: Parse -> Compile (JIT) -> Execute.
  • Call Stack: This is where the actual code execution happens. JavaScript is single-threaded, meaning it has only one Call Stack and can do one thing at a time.

Q. Synchronous vs Asynchronous Execution

  • Synchronous (Blocking): Code executes line by line. If line 2 takes 5 seconds, line 3 will NOT run until line 2 finishes. It blocks the main thread.
  • Asynchronous (Non-Blocking): Heavy tasks (like reading a file or fetching an API) are offloaded to the background (Web APIs / libuv). The main thread continues running the next lines immediately. When the background task finishes, its callback is executed later.
मराठी सारांश:
  • Synchronous म्हणजे एका रांगेत काम करणे (एकाचे काम झाल्याशिवाय दुसऱ्याचा नंबर लागणार नाही).
  • आणि Asynchronous म्हणजे जे काम वेळ खाऊ आहे (जसे Database मधून data आणणे), ते काम background ला देऊन पुढचे काम चालू ठेवणे.

Q. The Event Loop, Task Queue, and Microtask Queue

Definition: The Event Loop is a continuous process that checks if the Call Stack is empty. If the stack is empty, it pushes waiting callbacks from the Queues into the Call Stack to be executed.
  • Web APIs / C++ APIs: They handle async tasks like setTimeout, API calls, or File Reading in the background.
  • Microtask Queue: Higher priority queue! Promises (.then) and process.nextTick callbacks go here.
  • Macrotask Queue (Task Queue): Lower priority queue. Callbacks from setTimeout, setInterval, and I/O operations go here.

Interview Questions (Detailed)

Q1. Is JavaScript single-threaded or multi-threaded?
  • JavaScript itself is strictly single-threaded (it has only one Call Stack).
  • However, the environment (Node.js or Browser) provides background threads (like libuv thread pool).
  • These threads handle heavy async tasks, making the overall architecture feel multi-threaded.
Q2. Between setTimeout and Promise.resolve().then(), which one executes first?
  • The Promise will execute first because Promise callbacks go to the Microtask Queue, which has higher priority than the Macrotask Queue (where setTimeout goes). The Event Loop always empties the Microtask Queue before touching the Macrotask Queue.

  • 3. ACK: Client says "Confirmed."

Chapter 21: Encoding & Data Representation

Q. What is Encoding in Node.js?

Definition: Encoding is the way data is represented or converted between human-readable text and binary data (raw bytes).
  • When you read a file using fs.readFileSync("demo.txt") without specifying an encoding, Node.js returns a Buffer (raw bytes).
  • If you specify an encoding like "utf8", Node.js converts those bytes into a human-readable String.
  • Formula: Buffer (Bytes) + Encoding = Text (String)

Q. Common Encodings in Node.js

  • 1. UTF-8: The most commonly used text encoding. It supports almost all writing systems, including English, Marathi, Chinese, and Emojis (😊).
  • 2. ASCII: Represents a limited set of 128 characters (A-Z, 0-9, basic punctuation). It cannot represent Emojis or Marathi/Hindi text.
  • 3. Base64: Represents binary data as text. Useful when you need to send binary data (like images or tokens) over systems that only expect text (like JSON or URLs).
  • 4. Hex: Represents binary data using hexadecimal characters (0-9, a-f). Commonly used for debugging, hashes, and cryptography.
Code Example: Converting to Base64 and Hex
const buffer = Buffer.from("Hello");

// Convert to Base64
console.log(buffer.toString("base64")); // Output: SGVsbG8=

// Convert to Hex
console.log(buffer.toString("hex")); // Output: 48656c6c6f

Chapter 22: State Management (Cookies, Sessions, LocalStorage)

Q. Why do we need State Management?

Concept: HTTP is a Stateless Protocol. This means every request is completely independent. When you log in, the server immediately forgets who you are on the very next page load. To solve this, we use State Management techniques like Cookies and Sessions so the server can "remember" you.

Q. What is a Cookie?

  • A Cookie is a small piece of data (~4KB) stored on the Client-Side (User's Browser).
  • It is sent automatically with every HTTP request to the server.
  • Use Cases: Storing preferences (Dark Mode), small tracking identifiers, or Session IDs.
  • Security: Less secure because it is stored on the client side and can be modified.

Q. What is a Session?

  • A Session stores user data on the Server-Side (in Memory, Database, or Redis).
  • How it works:
  • When a user logs in, the server creates a Session and generates a unique Session ID.
  • This ID is sent to the browser and saved as a Cookie.
  • On the next request, the browser sends the Session ID back.
  • The server looks up the corresponding data in its database.
  • Security: More secure because sensitive data (like passwords or cart items) stays on the server.
मराठी सारांश:
  • HTTP हा भुलक्कड (Stateless) आहे.
  • तो युजरला लगेच विसरतो.
  • म्हणून आपण Cookie वापरतो.
  • Cookie म्हणजे एक छोटी पावती (Token) जी Browser स्वतःकडे ठेवतो.
  • Session म्हणजे मुख्य रजिस्टर जे Server कडे असते.
  • Browser ती पावती (Cookie) दाखवतो आणि Server रजिस्टर (Session) मधून ओळखतो की हा कोण आहे.

Q. LocalStorage vs SessionStorage

  • LocalStorage: Stores data in the browser persistently. Data stays even if you close the browser and restart your computer. (Max size ~5MB).
  • SessionStorage: Temporary storage. Data is completely cleared the moment you close the browser tab. (Max size ~5MB).

Chapter 23: MVC Architecture

Q. What is MVC?

Definition: MVC stands for Model-View-Controller. It is a popular architectural pattern used to structure software applications by separating concerns into three logical parts.
  • 1. Model (Data): Represents the database structure and business logic. It handles saving, fetching, and updating data. (e.g., models/product.js).
  • 2. View (UI): Represents what the user sees. It displays the data sent by the controller in HTML/EJS/HBS format. (e.g., views/index.ejs).
  • 3. Controller (Brain): The middleman. It receives requests from the user, asks the Model for data, and then passes that data to the View to be rendered. (e.g., controllers/shop.js).

Chapter 24: Environment Variables (dotenv)

Q. What are Environment Variables and `.env` files?

Definition: Environment Variables are values that affect the way a process runs on an operating system. In Node.js, we use a .env file to store sensitive data like API keys, Database Passwords, and Ports. We should never hardcode these in the main code.
  • Why? If you hardcode a database password in app.js and upload it to GitHub, hackers can steal your data.
  • How? We use a package called dotenv (npm install dotenv).
  • Usage: Create a .env file. Add values like PORT=3000. Then in code, use require('dotenv').config() and access it via process.env.PORT.
  • Security Rule: ALWAYS add .env to your .gitignore file so it never goes to GitHub.
मराठी सारांश:
  • आपण कधीही Password किंवा API Key थेट कोडमध्ये लिहीत नाही, कारण ते GitHub वर public होऊ शकतात.
  • आपण ते .env फाईलमध्ये ठेवतो आणि process.env वापरून वाचतो.

Chapter 25: CORS (Cross-Origin Resource Sharing)

Q. What is CORS and why does the browser block requests?

Concept: Browsers have a security feature called Same-Origin Policy (SOP). It prevents a frontend running on http://localhost:3000 from calling a backend API running on http://localhost:5000. To allow this cross-origin request, the backend must explicitly enable CORS.
  • To fix CORS errors in Express, we install the cors package.
  • npm install cors
  • Usage: const cors = require('cors'); app.use(cors());
  • You can also configure it to only allow specific domains (e.g., app.use(cors({ origin: 'http://my-frontend.com' }))).

Chapter 26: Authentication & Password Hashing

Q. Why do we hash passwords (bcrypt)?

  • Never store plain-text passwords in the database (e.g., password: "12345"). If the database is hacked, user accounts are compromised.
  • We use hashing (like the bcrypt package). It turns "12345" into a random string like $2b$10$xyz....
  • Hashing is one-way. You cannot decrypt it back to "12345". During login, bcrypt simply hashes the entered password again and checks if it matches the stored hash.

Q. What is JWT (JSON Web Token)?

Definition: JWT is a standard way for creating access tokens. Instead of keeping user state on the server (like Sessions), the server gives the client a JWT token after a successful login. The client sends this token in headers (Authorization: Bearer ) for future requests.
मराठी सारांश:
  • Bcrypt ने आपण पासवर्ड असा बदलतो की तो परत मूळ रूपात वाचता येत नाही.
  • आणि JWT म्हणजे एक 'Digital Entry Pass' जो Server ब्राउझरला देतो.
  • ब्राउझर प्रत्येक वेळी तो पास दाखवून सांगतो की "मी आधीच Login केले आहे".

Chapter 27: File Uploads (Multer)

Q. How do we upload files/images in Node.js?

  • When sending files from a frontend form, the encoding type must be multipart/form-data.
  • Standard body-parsers cannot read files. We must use a package like Multer.
  • Multer processes the incoming files and saves them to a destination folder (e.g., multer({ dest: 'uploads/' })).

Chapter 28: Global Error Handling Middleware

Q. How do we handle errors cleanly in Express?

  • If an error occurs deep inside a route, Node.js might crash or the user might get a blank screen.
  • Express has a special Error-Handling Middleware. It must have exactly 4 arguments: (err, req, res, next).
  • Whenever you call next(error) in a route, Express skips all normal routes and jumps straight to this error-handling middleware.
  • It should be placed at the very end of your app.js file.

Chapter 29: Child Processes & Worker Threads

Q. How does Node.js handle CPU-heavy tasks if it is single-threaded?

Concept: Node.js is great for I/O tasks (database, network) but terrible for heavy CPU tasks (video processing, complex math) because it blocks the single thread.
  • To solve this, Node.js provides Worker Threads and Child Processes.
  • Child Process: Spawns a completely new Node.js instance (heavy).
  • Worker Threads: Spawns a background thread within the same process that shares memory (lighter and better for CPU tasks).

Chapter 30: Production Process Management (PM2)

Q. What happens if our Node.js app crashes in production?

  • If you start an app with node app.js and an error occurs, the server stops. Your website goes down until you manually restart it.
  • In production, we use a Process Manager like PM2 (npm install -g pm2).
  • Benefits of PM2:
  • Automatically restarts the app if it crashes.
  • Keeps the app running in the background even if you close the terminal.
  • Can run multiple instances of the app to balance the load (Cluster mode).

  • कारण जर कधी एरर आला आणि सर्व्हर बंद पडला, तर PM2 त्याला सेकंदात आपोआप परत चालू (restart) करतो!
