01. What is Amazon S3?

Amazon S3 is a highly scalable, distributed object storage service. Unlike local hard drives or virtual block storage, S3 stores files as objects identified by unique keys inside buckets.

🌐 हिंदी स्पष्टीकरण — Amazon S3 क्या है?

Amazon S3 एक object-storage सेवा है, जिसमें data को bucket और key से रखा और प्राप्त किया जाता है। S3 Standard उच्च durability के लिए बनाया गया है, लेकिन durability का अर्थ zero risk, availability या backup नहीं है। Versioning और recovery controls अलग से configure करें।

02. Why Do We Need S3? The Problem with Server Disks

Saving user uploads directly to the local server disk via fs.writeFile() creates three critical production bottlenecks:

💥 1. Server Disk Exhaustion

1,000 users uploading 500 MB videos will fill a 50 GB server SSD in minutes, crashing the operating system and database.

🔀 2. Multi-Server State Split

Behind a Load Balancer, a file uploaded to Server A does not exist on Server B, causing random 404 Not Found errors on subsequent requests.

📦 3. Container Destruction

Docker containers on ECS and Kubernetes are ephemeral; restarting or redeploying destroys all local files permanently.

🌐 मराठी स्पष्टीकरण — सर्व्हरवर फाईल्स का सेव्ह करू नयेत?

जर युझरने सर्व्हरच्या हार्ड डिस्कवर थेट ५०० MB चा व्हिडिओ सेव्ह केला, तर काही वेळात सर्व्हरची मेमरी भरेल आणि ॲप क्रॅश होईल. तसेच लोड बॅलन्सरवर अनेक सर्व्हर्स असल्यास एका सर्व्हरवरील फाईल दुसऱ्याला दिसत नाही. म्हणून सर्व सर्व्हर्स **S3** या एकाच मध्यवर्ती क्लाऊड स्टोरेजला जोडले जातात.

08. S3 Security Architecture & The 4 Pillars

Production enterprise security requires a defense-in-depth approach:

🔒 Block Public Access

Master account-level and bucket-level kill-switch ensuring no public ACL or policy can expose private data.

🛡️ IAM Roles

Least privilege access granted to EC2/ECS tasks without hardcoding static AWS Access Keys in source code.

📜 Bucket Policies

Resource policies enforcing HTTPS TLS 1.2+ encryption in transit (aws:SecureTransport: false DENY).

🔑 KMS Encryption

Server-side encryption at rest using AES-256 (SSE-S3) or Customer Managed Keys (SSE-KMS) with CloudTrail audit logs.

09. Presigned URLs (Upload & Download Direct to S3)

Never route multi-megabyte user file uploads through your Fastify API server. Generate an ephemeral Presigned PUT URL:

A presigned URL is a bearer credential: anyone who obtains it can use it until expiry, within the signing principal's permissions. A presigned PUT can overwrite its target key. Use authorized, unpredictable keys and independently validate content and size.

services/s3Presign.js (Node.js SDK v3) 
import { S3Client, PutObjectCommand } from "@aws-sdk/client-s3";
import { getSignedUrl } from "@aws-sdk/s3-request-presigner";

const s3Client = new S3Client({ region: "ap-south-1" });

export async function generateUploadUrl(key, contentType, expiresInSeconds = 300) {
  const command = new PutObjectCommand({
    Bucket: process.env.AWS_S3_BUCKET,
    Key: key,
    ContentType: contentType
  });

  // Client has 5 minutes to complete the upload
  const presignedUrl = await getSignedUrl(s3Client, command, { expiresIn: expiresInSeconds });
  return { presignedUrl, key };
}
🌐 मराठी स्पष्टीकरण — Presigned URL चा फायदा

जर ५०० MB चा व्हिडिओ थेट Node.js सर्व्हरवर पाठवला, तर सर्व्हरची रॅम आणि नेटवर्क संपून जाते. Presigned URL वापरल्याने Fastify फक्त ५ मिनिटांसाठी वैध असलेली एक तात्पुरती सुरक्षित लिंक बनवून युझरला देते. युझरचा फोन किंवा ब्राउझर थेट AWS S3 वर फाईल अपलोड करतो, ज्यामुळे Node.js सर्व्हर एका सेकंदात हजारो युझर्स हाताळू शकतो!

15. Senior Interview Questions & Architectural Answers

Q01 What is Amazon S3 and how is it fundamentally different from a traditional filesystem?
▼

English Answer: Amazon S3 is an object store, not a hierarchical file system. Standard filesystems use directory trees, inode locks, and POSIX file handles. S3 is a flat key-value store where the "folder path" is simply an arbitrary UTF-8 string prefix. It scales infinitely to petabytes and is accessed exclusively via HTTP REST APIs.

🌐 हिंदी स्पष्टीकरण

S3 हे कॉम्प्युटरवरील नेहमीच्या फोल्डर सिस्टीमसारखे नसते. यात खरे फोल्डर्स नसून प्रत्येक फाईल एका युनिक की (Key) ने ओळखली जाते. हे स्टोरेज कधीही संपत नाही आणि इंटरनेटवरून थेट REST API द्वारे ॲक्सेस केले जाते.

Q02 Why should multi-megabyte file uploads never pass through Fastify or Node.js?
▼

English Answer: Node.js operates on a single-threaded event loop. Proxying large 500 MB video streams saturates network sockets, consumes heap memory buffers, and blocks event loop tick cycles. By generating an S3 Presigned URL, Fastify only handles authentication (35ms), and the client streams raw payload bytes directly into Amazon S3.

🌐 मराठी स्पष्टीकरण

मोठ्या फाइल्स सर्व्हरवरून पाठवल्यास Node.js ची रॅम आणि बँडविड्थ संपून सर्व्हर स्लो होतो. Presigned URL वापरल्याने युझर थेट S3 वर फाईल अपलोड करतो, ज्यामुळे API मोकळा राहतो आणि सेकंदात हजारो युझर्सना सेवा देऊ शकतो.

Q03 How does S3 achieve 99.999999999% (11 9s) durability?
▼

English Answer: S3 Standard is designed for 99.999999999% durability through redundant storage across multiple Availability Zones. Durability differs from availability and backup; use versioning, replication, and recovery controls for deletion or application-level corruption.

🌐 मराठी स्पष्टीकरण

S3 Standard कई Availability Zones में redundant storage के साथ उच्च durability के लिए बनाया गया है। इसे fixed replica count, availability या backup guarantee न कहें; accidental deletion और application corruption के लिए अलग recovery controls रखें।

Q04 Explain the S3 Multipart Upload workflow and why it is critical for fault tolerance.
▼

English Answer: Multipart upload sends parts independently and supports parallel transfer. Current documented part sizes are 5 MiB–5 GiB, with up to 10,000 parts and no minimum for the final part. Failed parts can be retried; configure lifecycle cleanup for abandoned uploads.

🌐 मराठी स्पष्टीकरण

५ GB ची फाईल १००-१०० MB चे तुकडे करून पाठवली जाते. इंटरनेट बंद पडल्यास फक्त फेल झालेला तुकडाच पुन्हा पाठवला जातो, संपूर्ण ५ GB फाईल पुन्हा पाठवावी लागत नाही.

Q05 What is Origin Access Control (OAC) in Amazon CloudFront?
▼

English Answer: OAC is AWS's modern SigV4 security mechanism replacing legacy OAI. It ensures the S3 bucket remains 100% private with Block Public Access enabled. CloudFront edge servers cryptographically sign origin requests, and the S3 bucket policy denies all traffic except requests originating from your specific CloudFront distribution ARN.

🌐 मराठी स्पष्टीकरण

OAC मुळे तुमचा S3 बकेट पूर्णपणे प्रायव्हेट राहतो. कोणीही थेट S3 लिंकवरून फाईल डाऊनलोड करू शकत नाही; फक्त तुमच्या अधिकृत CloudFront CDN द्वारेच फाईल पाहिली जाऊ शकते.

हिंदी Interview Perspective

  • Durability बनाम availability: S3 durability को backup न कहें; accidental deletion और application corruption के लिए versioning तथा recovery plan समझाएँ।
  • Presigned URL: इसे expiry और signing principal की permissions वाला bearer credential मानें। Target-key overwrite, file validation और multipart cleanup का ज़िक्र करें।
  • Object keys: ये opaque strings हैं, filesystem paths नहीं। Generated keys collision और unauthorized overwrite घटाते हैं।
  • Performance: baseline request-rate guidance को hard limit न बताएं; gradual scaling और `503 Slow Down` handling जोड़ें।
  • CloudFront costs: S3 transfer, S3 requests और CloudFront delivery charges को अलग-अलग समझाएँ।
